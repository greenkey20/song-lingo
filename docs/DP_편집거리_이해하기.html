0. 이 문서를 읽는 법

DP(동적 계획법)는 문법이나 라이브러리 사용법과 달리, 문제를 작은 문제로 쪼개고 작은 문제의 답을 어떻게 재사용할지 스스로 설계하는 사고방식입니다. 알고리즘 문제를 직접 풀어 본 경험이 없으면 이 코드가 낯선 것이 당연합니다.

추천 순서: 코드를 먼저 읽지 말고, 종이에 표를 만들 수 있는 상태부터 만듭니다. 그다음 코드가 그 표를 어떻게 채우는지 연결합니다.
  1. 1~5장을 읽으며 작은 예시(I love you / I like you)의 표를 손으로 따라 합니다.
  2. 6장에서 칸을 한 개씩 넘기며 "어느 세 칸을 보고 왜 그 값이 됐는지" 확인합니다.
  3. 11장 연습 모드에서 빈 표를 먼저 채워 보고 채점합니다(예측해 본 뒤 확인하는 것이 가장 효과가 큽니다).
  4. 8·9장으로 backtrace()와 scoring.py 전체 흐름을 연결합니다.

이 문서를 읽고 나서 스스로 설명할 수 있어야 하는 것 세 가지

  • 왜 표 d의 크기가 (n+1) × (m+1)인가?
  • 왜 d[i][j]는 위쪽·왼쪽·대각선 왼쪽 위 세 칸만 참조하는가?
  • 왜 그 세 값 중 최솟값을 고르면 전체 최소 편집 거리가 되는가?

이해의 기준은 "코드를 다시 쓸 수 있는가"가 아니라 "왜 이런 점화식이 성립하는지 설명할 수 있는가"입니다.

1. 이 함수가 푸는 문제

edit_matrix()는 두 문장이 얼마나 다른지 계산하기 위한 함수입니다. SongLingo에서 정답 문장과 STT가 인식한 문장을 비교하는 것이 그 용도입니다.

정답 (Reference)I love you
인식 (Hypothesis)I like you
차이love → like 로 바뀜 = 치환 1회
최소 편집 거리1

사용할 수 있는 수정은 세 가지이고, 각각 1회로 셉니다.

연산의미예시
치환 (S, Substitution)기존 단어를 다른 단어로 변경love → like
삭제 (D, Deletion)정답에는 있지만 인식 결과에는 없는 단어I love you → I you
삽입 (I, Insertion)인식 결과에만 있는 단어I you → I really you

이 세 연산으로 두 문장을 같게 만드는 최소 횟수가 Levenshtein 거리(편집 거리)입니다. WER은 이 횟수를 정답 단어 수로 나눈 값입니다.

WER = (S + D + I) / N

그런데 컴퓨터는 문장을 통째로 비교하지 않고, 두 문장의 앞부분부터 조금씩 늘려 가며 가능한 수정 방법 중 최소 횟수를 구합니다. 그 "앞부분"이 DP의 작은 문제입니다.

2. 표의 한 칸이 뜻하는 것: d[i][j]

d[i][j] = 정답의 앞 i개를 인식 결과의 앞 j개로 바꾸는 데 드는 최소 수정 횟수

이 문장을 확실히 이해하면 DP의 절반은 이해한 것입니다. 앞으로 쓰는 데이터는 이렇습니다.

ref = ["I", "love", "you"]
hyp = ["I", "like", "you"]

변수자료형값(예시)의미

2-2. 왜 2차원 표인가

정답 쪽 앞부분 길이(0~3)와 인식 쪽 앞부분 길이(0~3)를 둘 다 기준으로 삼기 때문입니다. 두 길이의 모든 조합이 부분 문제이므로 4 × 4 = 16칸이 필요합니다.

예: d[2][2]는 ref[:2]=["I","love"]를 hyp[:2]=["I","like"]로 바꾸는 최소 횟수이고 값은 1입니다. 즉 d[i][j]는 "표의 한 칸"이 아니라 부분 문제 하나의 정답입니다.

추가 Python 용어 정리
  • 슬라이스 ref[:2]: 앞에서 2개를 잘라 온 새 리스트(["I","love"]). 문서의 "앞 i개"는 ref[:i]입니다.
  • 부분 문제(subproblem): 원래 문제와 같은 모양이지만 입력이 더 짧은 문제. 여기서는 (ref[:i], hyp[:j]) 한 쌍이 부분 문제 하나입니다.
  • 토큰(token): 비교의 단위. WER에서는 단어, CER에서는 글자 하나입니다. 이 함수는 토큰이 문자열이기만 하면 단어든 글자든 똑같이 동작합니다(==로 비교 가능하면 됩니다).

3. 코드를 한 줄씩: 표 만들기와 초기화

def edit_matrix(ref, hyp):
    n, m = len(ref), len(hyp)
    d = [[0] * (m + 1) for _ in range(n + 1)]
    for i in range(n + 1):
        d[i][0] = i          # 인식 결과가 비어 있으면 정답 i개를 모두 삭제해야 한다
    for j in range(m + 1):
        d[0][j] = j          # 정답이 비어 있으면 인식 결과 j개가 모두 삽입이다
    for i in range(1, n + 1):
        for j in range(1, m + 1):
            cost = 0 if ref[i - 1] == hyp[j - 1] else 1
            d[i][j] = min(d[i - 1][j] + 1,        # 삭제
                          d[i][j - 1] + 1,        # 삽입
                          d[i - 1][j - 1] + cost) # 일치 또는 치환
    return d

3-1. n, m = len(ref), len(hyp)

두 값 모두 int입니다. 예시에서는 n = 3, m = 3.

3-2. d = [[0] * (m + 1) for _ in range(n + 1)]

안쪽부터 읽습니다. [0] * (m + 1)은 [0, 0, 0, 0](0이 m+1개). 이 한 줄(행)을 n + 1번 만들어 바깥 리스트에 담습니다. 결과는 4행 4열의 0으로 채운 표이고, 자료형은 list[list[int]]입니다.

왜 + 1인가? 앞부분의 길이가 0(빈 문장)부터 n(전체)까지이기 때문입니다. 길이 0, 1, 2, 3이면 4가지이므로 단어 수보다 하나 더 필요합니다.

쓰면 안 되는 형태: d = [[0] * (m + 1)] * (n + 1) 
bad = [[0] * 3] * 3
bad[0][0] = 9
print(bad)    # [[9, 0, 0], [9, 0, 0], [9, 0, 0]]  ← 세 행이 같은 리스트 하나를 가리켜서 한 곳을 바꾸면 전부 바뀐다
실행 확인 리스트 컴프리헨션 for _ in range(n + 1)은 행마다 새 리스트를 만들기 때문에 올바른 방법입니다.

3-3. 첫 번째 열: d[i][0] = i

첫 열은 j = 0, 즉 인식 결과가 빈 문장인 경우입니다. 정답에 단어가 i개 있고 인식이 비어 있으면, i개를 전부 삭제해야 하므로 비용이 i입니다.

정답인식필요한 삭제
[][]0
["I"][]1
["I","love"][]2
["I","love","you"][]3

3-4. 첫 번째 행: d[0][j] = j

이번에는 정답이 빈 문장이고 인식에 단어가 j개 있습니다. 정답이 비어 있으니 인식의 단어 j개는 전부 삽입입니다.

정답인식필요한 삽입
[][]0
[]["I"]1
[]["I","like"]2
[]["I","like","you"]3

이 두 가지(첫 열 = 삭제만, 첫 행 = 삽입만)가 DP의 초기값(base case)입니다. 초기화가 끝난 표는 아래와 같습니다. 초록색 칸이 이미 정해진 값이고, 점선 칸은 아직 계산하지 않은 칸입니다.

4. 핵심: 왜 세 값 중 최솟값인가

정답의 앞 i개를 인식의 앞 j개로 바꾼다고 합시다. 두 쪽의 마지막 단어(ref[i-1], hyp[j-1])를 어떻게 처리하느냐가 전부이고, 가능한 경우는 딱 세 가지입니다.

방향무슨 일이 일어났나식
↑ 위 삭제정답의 마지막 단어 ref[i-1]을 지웠다. 그 앞까지(ref[:i-1])는 hyp[:j]로 이미 맞춰 둔 상태.d[i-1][j] + 1
← 왼쪽 삽입인식의 마지막 단어 hyp[j-1]이 정답에 없는데 끼어들었다. 그 앞까지는 이미 맞춰 둔 상태.d[i][j-1] + 1
↖ 대각선 일치/치환두 마지막 단어를 서로 짝지었다. 같으면 추가 비용 0, 다르면 치환 1. 그 앞까지는 이미 맞춰 둔 상태.d[i-1][j-1] + cost

이 셋 중 가장 적은 횟수를 고르면 됩니다. 그것이 다음 코드입니다.

d[i][j] = min(d[i - 1][j] + 1,          # ↑ 삭제
              d[i][j - 1] + 1,          # ← 삽입
              d[i - 1][j - 1] + cost)   # ↖ 일치 또는 치환

DP의 사고방식이 여기서 드러납니다. 현재 문제의 답을, 이미 구해 둔 더 작은 문제들의 답으로 만듭니다. 그래서 위·왼쪽·대각선 왼쪽 위 칸이 먼저 채워져 있어야 하고, 이것이 이중 for를 "행은 위에서 아래로, 각 행은 왼쪽에서 오른쪽으로" 돌리는 이유입니다.

추가 채우는 순서와 의존 관계

빨간 숫자가 채우는 순서입니다(i=1..3, j=1..3). 어느 칸이든 그 칸의 위·왼쪽·대각선 왼쪽 위는 항상 더 먼저(또는 초기화로) 채워져 있습니다.

j=1j=2j=3
i=1123
i=2456
i=3789

예: 5번 칸 d[2][2]는 1번(대각선), 2번(위), 4번(왼쪽)을 참조합니다. 모두 5보다 먼저 채워졌습니다.

5. 실제 데이터로 표 채우기

ref = I love you, hyp = I like you로 아홉 칸을 순서대로 채웁니다. 아래 상자는 칸마다 세 후보를 계산한 과정입니다(코드로 만든 것입니다). 먼저 몇 칸은 직접 읽어 보세요.

5-1. 첫 칸 d[1][1]: ref[0]="I" vs hyp[0]="I"

두 단어가 같으므로 cost = 0.

방법계산결과
↑ 삭제d[0][1] + 12
← 삽입d[1][0] + 12
↖ 일치d[0][0] + 00

최솟값 0 → d[1][1] = 0. 사람 눈에도 I와 I는 같으니 수정이 필요 없습니다.

5-2. d[1][2]: ref[0]="I" vs hyp[1]="like" (cost = 1)

방법계산결과의미
↑ 삭제d[0][2] + 13정답 I를 삭제
← 삽입d[1][1] + 11인식에 like가 더 끼어듦
↖ 치환d[0][1] + 12I를 like로 치환

→ d[1][2] = 1. 정답 I를 I like로 만들려면 like 하나를 삽입하면 됩니다.

5-3. d[2][2]를 집중해서 보기 — 이 칸이 핵심입니다

ref[:2] = ["I","love"], hyp[:2] = ["I","like"]. 마지막 단어는 love vs like로 다르므로 cost = 1.

방법이전 칸연산 비용합
↑ 삭제d[1][2] = 1+12
← 삽입d[2][1] = 1+12
↖ 치환d[1][1] = 0+11

→ d[2][2] = 1. "I love를 I like로 바꾸는 최소 횟수는 1회(love→like 치환)"라는 뜻입니다. 대각선 칸 d[1][1] = 0이 앞에서 이미 "I = I"로 해결되어 있었기 때문에 가능한 값입니다. 이것이 앞에서 구한 답을 재사용한다는 말의 실체입니다.

5-4. 9칸 전부 보기와 완성된 표

9칸 계산을 모두 펼치기 (코드가 계산한 것)

완성된 표입니다(초록 = 초기화, 회색 = 계산한 칸, 오른쪽 아래 칸이 답).

마지막 칸 d[n][m] = d[3][3] = 1이 전체 편집 거리입니다. score()가 이를 정답 단어 수 3으로 나눕니다.

WER = (S + D + I) / N = 1 / 3 ≈ 0.333
실행 확인 scoring.edit_matrix(["I","love","you"], ["I","like","you"]) = [[0,1,2,3],[1,0,1,2],[2,1,1,2],[3,2,2,1]]

6. 직접 움직여 보기

문장을 고르거나 직접 입력하고, ▶ 다음을 눌러 한 칸씩 진행하세요. 칸을 채울 때는 점선으로 표시된 세 이웃 칸(↑ 삭제, ← 삽입, ↖ 일치/치환)과 계산표를 보고, 표가 다 채워지면 이어서 역추적이 시작됩니다(8장). 작은 화살표(↖↑←)는 그 칸의 값을 만든 이웃을 뜻하고, 둘 이상 있으면 최적 경로가 여러 개라는 신호입니다.

입력은 프로젝트 영어 정규화와 같은 규칙(NFC → 소문자 → 구두점 제거, 아포스트로피 유지)을 거쳐 공백으로 나뉩니다. 단어는 각각 10개까지.

g 표: 최소 거리 경로들 중 "닮은 단어끼리 짝지은 정도"의 최댓값 (8장)

7. 왜 이것이 Dynamic Programming인가

DP는 흔히 "동적 계획법"으로 번역하지만 이름보다 다음 두 가지 성질이 중요합니다.

  1. 최적 부분 구조 (Optimal Substructure): 전체 문제의 최적해가 작은 부분 문제의 최적해로 구성됩니다. 예: d[2][2]를 만들 때 d[1][1], d[1][2], d[2][1]의 이미 구한 최적해를 씁니다.
  2. 중복되는 부분 문제 (Overlapping Subproblems): 여러 경로가 같은 작은 문제의 답을 필요로 합니다. 표에 한 번 적어 두면 다시 계산하지 않아도 됩니다.

DP 설계 요소로 요약하면 이렇습니다.

DP 설계 요소이 문제에서의 의미
문제 정의두 문장을 같게 만드는 최소 편집 횟수
상태 (State)d[i][j]
상태의 의미정답 앞 i개를 인식 앞 j개로 바꾸는 최소 비용
초기 상태 (Base case)d[i][0] = i, d[0][j] = j
점화식 (Recurrence)삭제·삽입·치환/일치 중 최솟값
계산 순서위쪽과 왼쪽이 먼저 채워지도록 행 우선 순회
최종 답d[n][m]
추가 표가 없으면 얼마나 많이 다시 계산할까

표(메모) 없이 같은 점화식을 재귀 호출로만 풀면 같은 (i, j)를 계속 다시 풉니다. 아래는 호출 횟수와 DP 표 칸 수를 비교한 것입니다. 정답·인식 단어 수를 바꿔 보세요.

n = mDP 표 칸 수 (n+1)(m+1)재귀 호출 수배율호출 수 (로그 길이)

호출 수 = c[i][j] = 1 + c[i-1][j] + c[i][j-1] + c[i-1][j-1] (i 또는 j가 0이면 1)를 표로 센 값입니다. 실행 확인 6×5(the cat sat on the mat / the cat sit on mat)는 실제 재귀 실행으로 5,479번 vs 42칸, 3×3(I love you / I like you)은 94번 vs 16칸이었고 이 표의 값과 같습니다.

복잡도와 메모리

정답 토큰 수를 N, 인식 토큰 수를 M이라 하면 현재 구현은 표 전체를 보관하므로 시간 O(N × M), 공간도 O(N × M)입니다. 한 문장 정도의 짧은 입력에서는 충분히 빠릅니다. 매우 긴 문서를 다루면 메모리도 고려해야 하는데, 거리 값만 필요하면 직전 행만 보관하는 방식도 있습니다 [일반 지식]. 다만 이 프로젝트는 역추적을 위해 표 전체가 필요하므로 전체 표를 둡니다.

8. 표를 채우는 것과 "어디가 틀렸는지"를 알아내는 것은 다릅니다

edit_matrix()는 숫자(최소 횟수)만 계산합니다. 예를 들어 d[3][3] = 1이라는 사실만 알려 주고, 어느 단어가 어떻게 바뀌었는지는 모릅니다. 그 일은 다음 함수가 합니다.

  • edit_matrix(): 최소 수정 횟수를 계산한다.
  • backtrace(): 완성된 표를 되짚어 수정 방법과 위치를 알아낸다.
  • score(): 치환·삭제·삽입 개수를 세고 WER/CER을 계산한다.

8-1. 역추적은 무엇을 확인하나

오른쪽 아래 칸 (n, m)에서 출발해 "이 값이 어느 이웃에서 왔는가"를 확인하며 (0, 0)까지 거슬러 갑니다. 확인 조건은 점화식의 거울상입니다.

이웃이 조건이 참이면 거기서 왔을 수 있다기록되는 것
↖ 대각선d[i][j] == d[i-1][j-1] + (ref[i-1] != hyp[j-1])같으면 "일치", 다르면 "치환"
↑ 위d[i][j] == d[i-1][j] + 1"삭제" (ref[i-1])
← 왼쪽d[i][j] == d[i][j-1] + 1"삽입" (hyp[j-1])

거꾸로 모으기 때문에 마지막에 ops[::-1]로 뒤집어서 문장 순서로 돌려줍니다. 6장 아래쪽의 역추적 단계에서 각 칸에서 이 세 조건이 참인지 거짓인지 직접 볼 수 있습니다.

8-2. 조건이 둘 이상 참이면? — 최적 경로가 여러 개

같은 최소 거리를 만드는 경로가 여러 개일 수 있습니다. 이때 오류율(거리 ÷ N)은 같지만 어떤 단어를 어떤 단어와 짝지었는지, S·D·I 구성은 달라질 수 있습니다.

정답 / 인식최적 경로 (모두 거리 같음)
a b / b a[a→b] [b→a] (S=2) · [+b+] a [-b-] (D=1,I=1) · [-a-] b [+a+] (D=1,I=1)
we'll sing together /
we are seeing together		3가지: [+we+] [we'll→are] [sing→seeing] together · [we'll→we] [+are+] [sing→seeing] together · [we'll→we] [sing→are] [+seeing+] together (모두 S=2, I=1, 거리 3)
실행 확인

둘째 예에서 단순히 if 순서로 고르면 첫 번째 경로가 되어 we'll↔are 같은 서로 닮지 않은 짝이 나옵니다. 사람이 보기에는 we'll↔we, sing↔seeing이 자연스럽습니다. 6장에서 위 예시를 고르고 "동률일 때"를 바꿔 가며 역추적 결과를 비교해 보세요.

8-3. _tie_scores()와 g 표: 프로젝트가 추가한 규칙

추가

_tie_scores()는 수업과 자습 노트북에 없는 이 프로젝트의 추가 규칙입니다. 최소 거리를 만드는 경로들 중에서 닮은 단어끼리 짝지은 정도의 합이 가장 큰 경로를 고르려고, d와 같은 크기의 표 g를 하나 더 만듭니다.

  • g[i][j] = ref[:i]와 hyp[:j]를 최소 비용으로 맞추는 경로들이 얻을 수 있는 닮음 점수 합의 최댓값. (float, d와 같은 (n+1)×(m+1) 크기)
  • 일치 = 1점, 치환 = _similarity(a, b)(0~1: 두 글자열이 닮은 정도), 삭제·삽입 = 0점.
  • 점화식 모양은 d와 같지만, min 대신 "d의 최소 조건을 만족하는 후보만" 모아 max를 씁니다. 즉 d가 어떤 경로가 허용되는지를 정하고, g는 허용된 경로 중 무엇을 고를지를 정합니다.
  • backtrace()는 각 칸에서 후보 중 (점수가 큰 것, 같으면 if 우선순위: 일치/치환 → 삭제 → 삽입)을 고릅니다.

핵심은 이 규칙이 거리를 바꾸지 않는다는 점입니다. 오류율은 그대로이고 표시(그리고 S·D·I 구성)만 사람이 이해하기 쉽게 정리합니다. 그래서 score()의 assert S + D + I == distance 검산이 어느 경로를 골라도 통과합니다.

_similarity(a, b): 같으면 1.0, 둘 다 한 글자면 0.0(우연히 비슷해 보이기 쉬워서), 그 밖에는 difflib.SequenceMatcher(None, a, b).ratio() = 2 × (공통 글자 수) ÷ (두 길이의 합). 예: sing↔seeing은 2×4/(4+6) = 0.8.

실행 확인 이 문서의 6장 도구는 위 규칙을 scoring.py와 똑같이 옮겨 구현했고, 여러 문장 쌍에서 scoring.backtrace()의 결과와 같은지 비교했습니다(14장 출처·검증 참고).

10. 다른 DP 문제를 만났을 때: 6가지 질문

이 코드에서는 삭제·삽입·치환 세 연산을 쓰지만, DP는 문제마다 점화식이 달라집니다. 연산을 외우지 말고 아래 질문을 순서대로 던지는 습관이 남아야 합니다.

#질문편집 거리에서의 답
1내가 구하려는 최종 답은 무엇인가?두 문장 전체의 최소 수정 횟수 = d[n][m]
2그 답을 작은 문제로 나눈다면 각 문제는 무엇을 뜻하는가?"정답 앞 i개 → 인식 앞 j개"의 최소 횟수
3작은 문제의 답을 저장하는 상태 변수는?2차원 표 d[i][j]
4현재 상태를 어떤 이전 상태들로 계산할 수 있는가?마지막 토큰의 운명 3가지 → d[i-1][j], d[i][j-1], d[i-1][j-1]
5계산을 시작할 초기값은?첫 행 d[0][j]=j, 첫 열 d[i][0]=i
6어떤 순서로 계산해야 필요한 이전 상태가 이미 완성돼 있는가?행 우선(위→아래, 왼→오른)
추가 Python 팁: 이 표를 코드로 보는 눈
  • "상태 = 무엇의 어떤 앞부분인가"를 먼저 한 문장으로 쓰고, 그 문장을 d의 첨자(i, j)에 대응시킵니다.
  • 점화식에서 i-1, j-1이 나오면 거의 항상 "마지막 요소를 하나 떼어 낸 더 작은 문제"입니다. 그때 마지막 요소는 ref[i-1]처럼 한 칸 앞 인덱스로 접근한다는 점(표는 +1 크기)을 같이 기억합니다.

11-2. 과정을 출력하는 학습용 함수

이 함수는 edit_matrix()와 같은 계산을 하되, 칸마다 세 후보를 모두 출력합니다. 노트북에 붙여 넣어 입력을 바꿔 가며 돌려 보세요.

def edit_matrix_trace(ref, hyp):
    """DP 표가 채워지는 모든 과정을 출력하는 학습용 버전 (scoring.edit_matrix와 같은 계산)."""
    n, m = len(ref), len(hyp)
    d = [[0] * (m + 1) for _ in range(n + 1)]
    for i in range(n + 1):
        d[i][0] = i
    for j in range(m + 1):
        d[0][j] = j
    print("초기 DP 표:")
    for row in d:
        print(row)
    for i in range(1, n + 1):
        for j in range(1, m + 1):
            ref_word = ref[i - 1]
            hyp_word = hyp[j - 1]
            cost = 0 if ref_word == hyp_word else 1
            delete_cost = d[i - 1][j] + 1
            insert_cost = d[i][j - 1] + 1
            replace_cost = d[i - 1][j - 1] + cost
            d[i][j] = min(delete_cost, insert_cost, replace_cost)
            print(f"\n[i={i}, j={j}] ref[{i-1}]={ref_word!r} vs hyp[{j-1}]={hyp_word!r} → cost={cost}")
            print(f"  삭제  d[{i-1}][{j}]   + 1    = {delete_cost}")
            print(f"  삽입  d[{i}][{j-1}]   + 1    = {insert_cost}")
            print(f"  일치/치환 d[{i-1}][{j-1}] + {cost}  = {replace_cost}")
            print(f"  → d[{i}][{j}] = min({delete_cost}, {insert_cost}, {replace_cost}) = {d[i][j]}")
    print("\n완성된 DP 표:")
    for row in d:
        print(row)
    return d

12. 자주 하는 오해와 함정

오해바로잡기
i, j가 단어 인덱스다"몇 개까지 보는가"라는 길이입니다. 단어는 ref[i-1], hyp[j-1]
표 크기는 n × m이다(n+1) × (m+1). 길이 0(빈 문장) 행·열이 있어야 초기값을 둘 수 있습니다
행이 hyp, 열이 ref다이 코드는 행 = 정답(ref), 열 = 인식(hyp). 위로 가면 ref 단어 삭제, 왼쪽으로 가면 hyp 단어 삽입
세 연산을 외워야 DP를 안다연산이 아니라 "상태의 정의 → 이전 상태 → 초기값 → 순서"가 DP입니다 (10장)
[[0]*3]*3도 같은 표다행들이 같은 리스트 하나를 공유합니다 (3-2)
최소 거리가 같으면 경로도 하나다경로는 여러 개일 수 있고, 거리(오류율)는 같아도 S·D·I 구성과 표시가 달라집니다 (8-2)
표를 채우면 틀린 위치도 안다표는 횟수만 줍니다. 위치는 backtrace()가 되짚어야 알 수 있습니다 (8)

13. 더 깊이: 왜 세 칸이면 충분한가

외부 검토에서 다음에 탐구해 보라고 남긴 질문 세 개에 대한 답을 정리했습니다.

Q1. d[i][j]가 세 칸만 참조해도 되는 이유 (경로 관점의 증명 스케치)

추가

주장: 모든 (i, j)에서 d[i][j] = min(d[i-1][j]+1, d[i][j-1]+1, d[i-1][j-1]+cost).

  1. 편집을 "정답 줄과 인식 줄을 위아래로 나란히 맞춰 쓴 것"(정렬)으로 보면, 정답 ref[:i]를 인식 hyp[:j]로 바꾸는 어떤 정렬이든 맨 오른쪽 열은 정확히 다음 셋 중 하나입니다. (둘 다 빈칸인 열은 의미가 없으므로 최소 비용 정렬에는 없습니다.)
    • (a) ref[i-1] 위에 빈칸 → ref[i-1]이 삭제된다
    • (b) hyp[j-1] 위에 빈칸 → hyp[j-1]이 삽입된다
    • (c) ref[i-1]과 hyp[j-1]이 한 열에 함께 → 짝지어진다 (같으면 일치, 다르면 치환)
  2. 각 경우에 남는 나머지 편집은 각각 (ref[:i-1], hyp[:j]), (ref[:i], hyp[:j-1]), (ref[:i-1], hyp[:j-1])를 바꾸는 더 작은 문제입니다.
  3. 전체가 최소이려면 남은 부분도 최소여야 합니다. 남은 부분이 최소가 아니라면 더 싼 것으로 바꿔 전체를 더 줄일 수 있기 때문입니다(최적 부분 구조).
  4. 따라서 최소 비용 = 세 경우의 (작은 문제 최솟값 + 이번 연산 비용) 중 최솟값입니다. 이것이 점화식입니다. 증명은 i + j에 대한 귀납법으로 완성됩니다. (기저: i = 0 또는 j = 0은 초기화 값.)

위는 증명의 뼈대(스케치)이며 엄밀한 수학적 증명 전체는 아닙니다 [일반 지식]. 자세한 증명은 알고리즘 교재의 Levenshtein 거리 항목을 참고하세요.

Q2. backtrace()는 어떤 조건으로 경로를 복원하나

8-1의 표입니다. 각 칸에서 "이 값이 이 이웃의 값에 연산 비용을 더한 값과 같은가"를 확인합니다. 같으면 그 이웃에서 왔을 수 있다는 뜻이고, 그쪽으로 한 칸 이동하면서 연산을 기록합니다. 조건이 하나만 참이면 경로가 하나로 정해지고, 둘 이상이면 8-2·8-3의 동률 처리가 일합니다.
