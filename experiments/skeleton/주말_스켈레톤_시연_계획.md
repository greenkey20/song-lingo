## 2. 발표를 한다면 무엇을 어떻게 하게 되는가 (예상)

발표 길이는 **[미확인]**이지만 보통 몇 분 안팎의 개인 발표이므로 아래 구조면 충분하다 **[추정]**. 계획서 5장의 보고 자료 구조(문제 → 설계 → 시연 → 평가 결과 → 한계)와 같다.

1. **문제 (30초)**: "좋아하는 외국어 노래의 문장을 정확히 따라 말하고 싶은데, 내 발음이 맞는지 확인하기 어렵다."
2. **설계 (1분)**: 데이터 흐름 한 장 — 듣기(TTS) → 따라읽기(녹음) → 인식(Whisper) → 채점(WER/CER) → 틀린 부분 표시. 수업에서 배운 것(013, 7강, 1~4강)과 자습한 것(WER/CER)을 구분해서 말한다.
3. **시연 (2분)**: 노트북에서 문장 하나를 듣고, 미리 녹음한 파일로 채점 결과를 보여 준다. **라이브가 부담이면 미리 실행해 둔 노트북 출력 또는 화면 녹화로 대체**해도 된다(아래 예상 화면).
4. **결과 (1분)**: 숫자 한두 개 — 예: 문장 10개 × 3회 처리 성공, 평균 WER/CER, 정규화 규칙에 따라 점수가 달라지는 예(구두점을 지우기 전 0.200 → 후 0.060 **[확인, 수업 제공 WAV 5개]**).
5. **한계와 배운 점 (30초)**: 점수는 발음 점수가 아니라 문장 인식 일치도, 녹음은 본인 한 명, 잡음 실험은 합성 잡음.

→ **발표 내용은 "내가 만든 것을 보여 주고 한계를 솔직히 말하는 것"이고, 새로운 연구 결과를 발표해야 하는 것이 아니다.** 부담을 줄이는 방법: 대본을 미리 써서 읽기, 시연은 미리 실행한 출력으로, 예상 질문(왜 이 주제인지, 점수가 믿을 만한지, 다음 단계는 무엇인지) 3개 준비.

### 예상 화면 (아직 구현 전의 모습, **실제 출력이 아님**)
```
문장 #3: "I want to explore the universe."
[▶ 기준 음성 재생]      ← OpenAI TTS로 만든 영어 음성 (노트북 오디오 플레이어)

내 녹음: data/recordings/s03_take1.m4a
Whisper(tiny) 인식: "I want explore a universe"

WER 0.333  (치환 1, 삭제 1, 삽입 0 / 정답 6단어)
I want [-to-] explore [the→a] universe        ← 틀린 부분 표시
```
채점과 틀린 부분 표시 부분은 이미 동작한다 **[확인]**: `scoring.wer("The cat sat on the mat.", "the cat sit on mat")` → `WER 0.333 (치환 1, 삭제 1)`, `the cat [sat→sit] on [-the-] mat`. 나머지(TTS, 녹음 인식)를 이어 붙이는 것이 이번 주말 작업이다.

## 3. 주말 스켈레톤: 범위와 시간 (합계 약 3~4시간 [추정])

**한 줄로 관통하는 데 필요한 것만** 만든다. 입력 상태 점검, 기록 CSV, 그래프, LLM, 재생 제어 HTML, 받아쓰기, L3는 **하지 않는다.**

| 단계 | 할 일 | 시간 | 완료 기준 |
|---|---|---|---|
| S0 | 준비 확인: `.env`의 `OPENAI_API_KEY`가 읽히는지(값은 출력 금지), 커널 `voice-ai`, Whisper 모델 재사용 | 15분 | 노트북에서 키 존재 여부 `True`, 모델 로딩 성공 |
| S1 | 연습 문장 **3개** 직접 작성(`sentences.csv`, 출처는 "직접 작성", 상업 가사 금지). 계획서 문장 설계 기준(5~12단어, 축약형 포함) | 20분 | CSV 3행 |
| S2 | TTS 1문장 생성·재생: 학습 저장소 `013_openai_api/OpenAI_API_Whisper_입문과 한국어 음성 AI 실습.ipynb`의 `text_to_wav`를 참고(모델·voice는 그 노트북 설정, 영어 지원 여부는 이때 확인) | 40분 | `data/tts_cache/`에 wav 생성, 재생됨 |
| S3 | 내 녹음 3개(iPhone 음성 메모 → AirDrop → `data/recordings/`) → `faster-whisper tiny`로 인식 (`language="en"`, `beam_size=1`) | 50분 | 인식 문장 3개 출력 |
| S4 | `practice.ipynb`에 S2·S3를 이어 붙이고 `scoring.wer`/`cer`/`format_diff`로 채점 표시 | 40분 | 문장 3개가 위 "예상 화면" 형태로 출력 |
| S5 | 노트북 전체 실행(위→아래) 후 화면 캡처 1장(개인용, 커밋 금지), 발표 대본 초안 5줄 | 30분 | 3분 안에 말로 설명 가능한지 직접 시험 |

- **Whisper 모델 재사용**: 학습 저장소에 이미 내려받은 모델(`../ict_innovation_sq_voice_ai/017_sound/models/`, 약 75MB, `models/`는 git 제외)이 있다. 복사하면 5분 넘는 다운로드를 건너뛴다: `cp -r ../ict_innovation_sq_voice_ai/017_sound/models ./models` **[확인: 폴더 존재]**.
- **실험·확인은 사용자가 직접 실행**한다(코드는 새 세션에서 같이 작성). 이번에 보는 값은 모두 참고용이다.
- 녹음은 노트북에서 직접 하지 않는다(`sounddevice` 없음). iPhone `.m4a`는 faster-whisper가 바로 읽는다 **[확인, 앞선 세션]**.
- **커밋 전**에 노트북 출력의 오디오 플레이어·경로를 지운다: `python scripts/scan_outputs.py`.

## 4. 일요일 저녁 판단 기준 (설문 응답 전)

아래를 스스로 점검한다. 정답은 없고 **자신에게 편한 선택**이면 된다.

- [ ] 스켈레톤이 끝까지 돌아 "예상 화면" 비슷한 출력이 나왔다 (안 돼도 **어디서 막혔는지**를 알게 된 것이 수확이다)
- [ ] 그 화면을 보며 "문제 → 설계 → 시연 → 한계"를 **3분 안에 말로 설명**해 봤다(혼자 또는 휴대폰 녹음으로)
- [ ] 발표 당일(11-12 목 18:00) 회사 일정이 가능하다
- [ ] 발표를 하면 얻는 것(경험, 우수상 후보)과 부담(긴장)을 비교해 봤다

**판단 가이드 [추정]**: 첫 항목과 둘째 항목이 되면 "발표 진행"을 선택해도 부담이 크지 않은 수준이다. 막혔거나 말이 안 나오면 발표 불가를 고르고(사유 입력란이 있다), 결과물 제출에만 집중해도 평가에는 문제가 없다. 응답 후 변경 가능 여부는 운영팀에 문의해 볼 수 있다 **[미확인]**.
