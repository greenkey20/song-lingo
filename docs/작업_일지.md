# 작업 일지 (song-lingo)

이 문서는 하루 작업을 짧게 남기는 일지입니다. 사용자가 Notion 일일 기록에 복사해 쓰고, 강사님과의 면담 때 보는 용도입니다. 양식은 계획서 9장의 일일 기록(날짜 · 한 일 · 막힌 점 · 내일 할 일 · 질문)을 따릅니다. 판단의 근거와 옵션 비교는 `프로젝트_안내_및_주제_검토.md`에 있고, 이 문서는 "무엇을 했고 각 파일이 무엇인지"만 적습니다.

> **AI가 쓴 코드를 이해하는 법**: 아래 파일 표의 **"수업과의 관계"** 열에서 '수업 코드 재사용'은 수업 자료로 복습하면 되고, **'수업에 없음'** 은 코드 주석과 이 표를 읽으며 따로 익힐 부분입니다. 새 코드에는 수업과 다른 부분을 주석에 `[수업에 없음]`으로 표시합니다.

  - **주석 보강** (#25): 기준을 정해(CLAUDE.md의 '주석 기준') `scoring.py`, `tts.py`, `stt.py`, `align.py`, `report.py`, `theme.py`, `spike/server.py`, `scripts/scan_outputs.py`에 적용했습니다. 모든 파일에 **수업과의 관계**(`[수업과 같음]`/`[수업에 없음]`과 출처)를 맨 위에 적었고, 수업에 없는 개념(`difflib`, `word_timestamps`, `vad_filter`, FastAPI, 정규식 등)에는 설명을 달았습니다. 코드는 AST 비교로 이전과 같음을 확인했고 테스트 65개가 그대로 통과합니다. 발견: WER·CER은 수업이 아니라 자습 노트북 기준이라 `scoring.py` 전체가 '수업에 없음'입니다.
  - **노트북 점검 스크립트** (#26): `scripts/check_notebook.py`. 노트북의 코드 셀을 차례로 실행해 끝까지 되는지 봅니다(`input()`은 준비한 글로, `plt.show()`는 PNG 저장으로 대신하고, 기본으로 `.env`를 읽지 않아 API 과금이 없음). 실제 `practice.ipynb`의 코드 셀 18개가 모두 실행되었고(약 22초) 테스트 6개를 추가했습니다.
  - **`quality.py` 기준값 확정** (#7): 상황별 녹음 6개와 소리 크기를 일부러 바꾼 실험으로 확인했습니다. Whisper tiny가 소리 크기에 매우 강해 초안 기준(-40 dBFS, 잘림 0.1%)이 정상 인식 녹음에도 경고를 내서 -55 dBFS, 최대 0.02, 잘림 1%로 완화하고, 인식이 깨진 '짧게 한마디' 녹음을 잡도록 '말한 시간 1.0초' 점검을 추가했습니다. 근거 표는 `quality.py` 맨 위에 있고, 잘림 1%는 사용자가 결정했습니다(바꾸려면 상수 하나). 테스트 5개 추가. 전체 실험표와 클리핑 설명은 검토 문서 8.25에 있습니다.

## 4. 용어·방법 메모

개발하면서 나온 낯선 용어와 검증 방법을 모아 둡니다. 날짜별 로그에는 "한 일"만 적고, 설명은 여기에 적습니다.

| 용어 | 뜻 | 이 프로젝트에서 쓴 곳 |
| --- | --- | --- |
| **헤드리스(headless) 실행** | 화면(창) 없이 터미널에서 코드를 실행하는 것. 그림은 창에 띄우지 않고 파일로 저장합니다. | 노트북의 코드 셀을 위에서부터 차례로 실행해, 코드를 옮긴 뒤에도 결과가 같은지 확인할 때 (AI 세션에서 사용) |
| **`Agg` 백엔드** | matplotlib이 화면 없이 이미지 파일만 만들게 하는 설정. | 헤드리스 실행과 `tests/test_visualisation.py`에서 사용 |
| **픽셀 비교** | 두 PNG 그림을 픽셀 값으로 비교해 같은지 보는 것(차이 0.0이면 완전히 같음). | 그림 함수를 노트북에서 `visualisation.py`로 옮길 때, 옛 노트북과 같은 그림인지 확인 (#23) |
| **리팩터링** | 동작은 그대로 두고 코드의 위치·구조만 정리하는 것. | 노트북 함수를 `tts.py`, `stt.py`, `audio.py`, `visualisation.py`로 분리 |
| **단위 테스트(`unittest`)** | 함수 하나가 기대한 값을 내는지 자동으로 확인하는 코드. 개인 녹음 대신 합성 신호(사인파)를 씁니다. | `tests/` |
| **정리본 커밋** | 노트북은 출력에 목소리·경로가 남을 수 있어서, 출력을 지운 복사본만 커밋하고 로컬 원본(출력 있음)은 그대로 둡니다. | `practice.ipynb` 커밋 때마다 (`scripts/scan_outputs.py`로 검사) |
| **커널 재시작** | 노트북이 이미 불러온 모듈은 파일을 고쳐도 새로 읽지 않습니다. 고친 모듈을 반영하려면 커널을 재시작합니다. | `.env` 키 교체, `theme.py`·`visualisation.py` 수정 후 |
| **클리핑(잘림)** | 마이크 입력이 너무 커서 파형의 꼭대기가 한계선(±1.0)에서 평평하게 잘리는 것. 찢어지거나 지직거리는 소리가 됩니다. | `quality.py` (한계선에 닿은 샘플의 비율, 1% 이상이면 경고) |
| **dBFS · RMS** | RMS는 소리의 평균 세기, dBFS는 그것을 디지털 최대치(1.0)를 0으로 한 데시벨로 나타낸 것. 0에 가까울수록 크고 −60 아래면 거의 안 들립니다. | `quality.py` (RMS < −55 dBFS면 '너무 작음') |
| **말한 시간** | 무음이 아닌 프레임이 차지하는 시간. 전체 길이가 충분해도 말은 잠깐뿐인 녹음을 잡습니다. | `quality.py` (1.0초 미만이면 경고) |
| **캐시** | 한 번 만든 결과를 저장해 다시 쓰는 것. | TTS 음성(`data/tts_cache/`), 호출 횟수 `tts.calls` |
| **flat 구조** | 모듈(.py)을 프로젝트 맨 위 폴더에 나란히 두는 방식. 작은 프로젝트에 흔하고 `import scoring`처럼 바로 부를 수 있습니다. | 지금의 song-lingo (`scoring.py`, `tts.py` … 가 루트에 있음) |
| **패키지 구조** | 모듈을 `songlingo/` 같은 폴더(`__init__.py` 포함)에 모아 `from songlingo import scoring`처럼 부르는 정석 방식. `pip install -e .`로 설치하면 어느 폴더에서든 불러 쓸 수 있습니다. 배포하거나 모듈이 많을 때 적합합니다. | 후속 이슈로 등록 (정리 시기는 L1 완료 뒤로 제안) |
| **`sys.path.insert`** | 파이썬이 모듈을 찾는 경로 목록에 폴더를 직접 추가하는 임시방편. flat 구조에서 `tests/`가 루트의 모듈을 찾으려고 씁니다. 패키지로 설치하면 필요 없어집니다. | `tests/test_*.py` 맨 위 |

### AI 세션의 검증은 "참고"입니다
AI 세션이 헤드리스로 돌린 결과는 **참고 baseline**입니다. 최종 확인은 VS Code에서 *File → Reload Notebook from Disk* 후 커널을 재시작하고 직접 실행해서 보는 것입니다.
