## 2. 1단계: 구간 고르기

### 2.1 곡 번호 보기
> **노트북에서는** 「곡 목록」 셀을 실행하면 번호, 파일 이름, 형식, **길이(초)**, 크기가 표로 출력으로 남습니다(터미널을 오가지 않아도 됨). 아래 명령은 터미널 방식입니다.

```bash
$PY scripts/separate_clip.py --list
```
- 영어 곡 58개가 `번호  파일이름` 형태로 나옵니다. 이 번호를 `--song`에 씁니다.
- **주의**: 번호는 `data/songs/en` 폴더의 파일 목록(이름순) 순서입니다. 곡을 폴더에 더하거나 빼면 번호가 바뀝니다. 그래서 `clips.csv`에는 번호가 아니라 **파일 이름**이 기록됩니다.

### 2.2 어떤 구간을 고를까 (제안)
- 구간은 **10~20초**, 가사가 있는 부분(간주·전주 제외), 문장이 중간에 끊기지 않게 시작합니다.
- **5~10개**를 아래처럼 섞습니다. 한 가지 유형만 고르면 "분리가 도움이 되는가"를 일반화할 수 없습니다.

  | 유형 | 개수(권장) | 이유 |
  |---|---|---|
  | 가사가 또렷한 곡(반주가 얇음, 한 사람이 부름) | 2~3 | 분리가 필요 없을 수도 있다는 기준선 |
  | 반주가 두꺼운 곡(밴드, 신스) | 2~3 | 분리 효과가 가장 크게 보일 수 있음 |
  | 합창·코러스·겹치는 목소리가 있는 구간 | 1~2 | 분리와 인식이 모두 어려운 경우 |
  | 빠른 랩·말에 가까운 곡 | 0~1 | 선택. 노래보다 낭독에 가까워 비교 대상으로 쓸 수 있음 |
- 원본 WMA가 **저음질**(확인한 1곡은 32 kHz, 34 kbps)이라 결과에 영향을 줄 수 있습니다. 이것은 실험의 한계로 8절에 적습니다.

### 2.3 시작 시각 찾기
- 곡을 재생 프로그램(VLC 등, WMA가 안 되는 앱이 있습니다)에서 열어 **가사가 시작하는 시각(초)**을 메모합니다.
- 어렵다면 일단 `--start 60`(1분)처럼 짐작으로 분리하고, 3단계에서 들어 보고 어긋났으면 `--start`를 바꿔 `--overwrite`로 다시 분리하면 됩니다.

선택 결과는 **8.1절 표**에 적습니다(곡 파일 이름·가사는 적지 않고 곡 번호만).

## 3. 2단계: 구간 자르기 → 듣고 확인 → 보컬 분리

> **11-03 개정**: 처음에는 자르기와 분리를 한 번에 했는데(구간당 1분 안팎), 8구간 중 2구간이 가사 구간이 아니어서 분리 시간이 낭비되었습니다(8.1절 아래 기록). 그래서 **먼저 자르기만(몇 초) → 원곡(mix)을 들어 구간 확인 → 맞는 구간만 분리** 순서로 바꿨습니다. 노트북은 ③a(자르기) → ④(듣기) → ③b(분리), 터미널은 아래 두 명령입니다.
> ```bash
> $PY scripts/separate_clip.py --song 6 --start 60 --duration 20 --id c01 --cut-only   # 자르기만
> afplay data/song_work/c01_mix.wav                                                    # 가사 구간이 맞는지 듣기
> $PY scripts/separate_clip.py --id c01 --separate-only                                # 맞으면 분리
> ```
> 어긋나면 `--start`를 바꿔 `--cut-only --overwrite`로 다시 자릅니다(그 구간의 옛 보컬 파일은 자동으로 지워집니다). 노트북 ③a는 `start`가 바뀐 구간만 알아서 다시 자릅니다.
> 아래 명령(자르기 + 분리를 한 번에)도 여전히 쓸 수 있습니다.

구간마다 한 번씩 실행합니다(`--id`는 구간 이름: `c01`, `c02`, …).
```bash
$PY scripts/separate_clip.py --song 6 --start 60 --duration 20 --id c01
```
- 처음 한 번은 Demucs 모델을 내려받습니다. **20초 구간에 1분 안팎**(내 컴퓨터에서 63.9초, 3.20배)이 걸립니다.
- 끝나면 이런 줄이 나옵니다: `분리 63.9초 (3.20배) | RMS dBFS 원곡 -13.0, 보컬 -21.0` 과 저장 경로 두 개.
- 만들어지는 것(모두 git 제외 폴더): `data/song_work/c01_mix.wav`(구간 원본), `c01_vocals.wav`(보컬), `clips.csv`(어느 곡의 어느 구간인지 목록).
- 같은 `--id`로 다시 하려면 `--overwrite`를 붙입니다(없으면 `이미 있는 구간입니다` 오류로 막힙니다).
- 여러 구간을 이어서 돌리려면 한 줄씩 차례로 칩니다(동시에 돌리지 않습니다. CPU를 나눠 써서 더 느려질 수 있습니다 [추정]).

### 3.1 분리가 제대로 됐는지 귀로 확인
```bash
afplay data/song_work/c01_mix.wav        # 구간 원본(끝까지 재생. 중간에 멈추려면 Ctrl+C)
afplay data/song_work/c01_vocals.wav     # 분리한 보컬
```
- 확인할 것: ① 시작·끝이 원하는 가사 구간인가 ② 보컬이 들리는가 ③ 반주가 얼마나 남아 있는가(조금 남는 것은 정상).
- 구간이 어긋나면 `--start`를 바꿔 `--overwrite`로 다시 분리합니다.
- 분리 품질에 대한 첫인상(좋음/보통/나쁨)을 8.1절 표 "분리 첫인상"에 적어 둡니다. 이것은 귀로 한 주관적 평가이고 숫자 결과와 비교하는 데 씁니다.

## 4. 3단계: 정답 가사 받아 적기

정답 파일은 `data/song_work/truth/c01.txt`처럼 **구간 id와 같은 이름**으로 만듭니다.

```bash
mkdir -p data/song_work/truth                # 폴더 만들기(한 번만)
touch data/song_work/truth/c01.txt         # 빈 파일 만들기(open -e는 없는 파일을 못 열어서 먼저 만듭니다)
open -e data/song_work/truth/c01.txt         # 맥 텍스트 편집기로 열기. VS Code로 열어도 됩니다.
```
- **인코딩은 UTF-8**, 줄바꿈은 자유입니다(프로그램이 줄바꿈과 연속 공백을 한 칸으로 합칩니다). 구두점·대소문자는 맞추지 않아도 됩니다(채점 때 정규화).
- 듣는 방법: **분리 전 원곡 `afplay data/song_work/c01_mix.wav`를 여러 번 듣습니다.** 정답을 분리된 보컬로 받아 적으면 분리에 유리하게 정답이 끌려갈 수 있어서, 정답은 원곡 기준으로 적고 보컬은 분리 품질을 보는 데만 씁니다. 반주 때문에 안 들리는 부분은 공식 가사 등 **내가 확인할 수 있는 자료를 개인 학습용으로 참고**해도 됩니다. 단, 그 가사를 저장소·문서·이슈에 붙이지는 않습니다.
- **규칙 (제안, 첫 실험의 기본)**: 그 구간에서 실제로 불린 **가사의 단어**를 적습니다.
  - 추임새·감탄(`oh`, `yeah`, `la la` 등)은 적지 않습니다. 대신 8.1절 표 "추임새" 칸에 있었는지 표시합니다(Whisper가 이것을 어떻게 다루는지 따로 볼 수 있게).
  - 반복되는 후렴은 불린 횟수만큼 적습니다.
  - 들리는 대로가 아니라 **가사에 적힌 단어**로 적습니다(`gonna`처럼 발음이 줄어도 가사가 `gonna`이면 `gonna`). 축약형·숫자는 채점할 때 통일 규칙(기본)이 적용됩니다.
- 확인:
  ```bash
  wc -w data/song_work/truth/c01.txt        # 단어 수. 20초 구간이면 보통 수십 단어 [추정]
  ```
  너무 적거나(5단어 미만) 너무 많으면(구간이 20초보다 길게 적힘) 구간과 맞는지 다시 봅니다.
- 정답을 받아 적는 사람이 나 하나라 **정답에도 오류가 있을 수 있습니다.** 헷갈린 단어는 8.1절 표 "의심" 칸에 몇 개인지 적습니다(단어 자체는 적지 않음).

## 5. 4단계: 비교 실행

### 5.1 먼저 짧게 (확인용, 1~2분)
```bash
$PY scripts/compare_clips.py --ids c01 --sizes tiny
```
- 구간 1개 × 소리 2(원곡, 보컬) × 크기 1 × VAD 끔 = **2번 인식**. 표가 나오는지만 봅니다.
- 오류가 나면 10절을 봅니다. 대표적으로 `준비가 덜 된 구간: c01(빠진 것: 정답)`은 정답 파일 이름이 틀렸거나 없다는 뜻입니다.

### 5.2 전체 (10~20분 [추정])

> **11-03 밤 개정**: 같은 입력도 노래에서는 실행마다 결과가 달라질 수 있어서(온도 폴백, 검토 문서 13.5) `--temperature` 옵션을 추가했습니다. **주 결과는 `--temperature 0.0`(폴백 없이 재현 가능)** 으로 내고, 기본 설정(`default`)을 `--repeats 3`으로 돌려 **흔들림 범위**(`micro_min`~`micro_max`)를 확인용으로 봅니다. 보고할 때는 어떤 temperature인지 항상 적습니다.

```bash
# (1) 주 결과: 재현 가능. 결과는 항상 같음
$PY scripts/compare_clips.py --sizes tiny base small --vad both --temperature 0.0
# (2) 확인용: 기본 설정(온도 폴백)을 3회 되풀이해 흔들림 범위를 봄 (tiny, base만 권장: small은 오래 걸림)
$PY scripts/compare_clips.py --sizes tiny base --vad off --temperature default --repeats 3
```
- (1)과 (2)는 같은 `results/song_compare/` 파일에 **덮어써서 저장**됩니다. (1)의 화면 표를 8.2절에 옮긴 뒤 (2)를 돌립니다(또는 `--temperature 0.0 default`로 한 번에).
- 화면의 `temp` 열: `T0.0` = 폴백 없음, `기본` = faster-whisper 기본. `runs`는 반복 수, `micro_min~max`는 반복 간 범위입니다.
- **읽는 법**: 원곡-보컬의 micro_WER 차이가 `기본` 설정의 `micro_min~max` 범위보다 크면 의미 있는 차이로 봅니다. 범위 안이면 흔들림과 구분되지 않습니다.
- 구간 N개 × 2 × 3 × 2번 인식(5개면 60번). 로컬이고 **API 과금은 없습니다.**
- `small`이 `models/`에 없으면 처음에 내려받아 시간이 더 걸립니다(디스크 여유가 적습니다: 약 7.6 GB). 부담되면 `--sizes tiny base`로 먼저 합니다.
- 끝나면 화면에 표 두 개가 나오고 파일 두 개가 저장됩니다.

  | 파일 | 내용 | 비고 |
  |---|---|---|
  | `results/song_compare/metrics.csv` | 점수표(S·D·I·N, WER, CER, 인식 시간) | 가사 없음 |
  | `results/song_compare/texts.csv` | 인식된 문장 | **가사**. Claude가 오류 분석에 읽고, 문서에는 옮기지 않음 |

## 6. 결과 읽는 법

화면의 두 표:
- **[1] 조건별 요약**: 한 줄이 (모델 크기, VAD, 소리) 조합입니다.
  - `micro_WER` = 오류 합 ÷ 정답 단어 합(긴 구간이 더 크게 반영, 기본 지표), `macro_WER/CER` = 구간별 평균, `sec` = 평균 인식 시간.
  - 같은 크기·VAD에서 `mix` 줄과 `vocals` 줄을 **위아래로 비교**합니다. vocals가 낮으면 분리가 도움이 된 것입니다.
- **[2] 구간 × 조건 WER**: 구간마다 원곡과 보컬 중 어느 쪽이 나은지 보입니다. 평균이 같아도 구간마다 반대일 수 있습니다.

주의할 점:
- **WER은 1을 넘을 수 있습니다**(삽입이 많으면). "일치율"로 해석하지 않습니다.
- 이 값은 **STT가 정답 가사를 얼마나 되살렸는가**이지 노래 실력이나 발음 평가가 아닙니다.
- 구간이 5~10개이고 곡 장르가 한정되어 **일반화하지 않습니다.** **같은 입력이어도 Whisper의 인식 결과가 실행마다 달라질 수 있습니다**(노래에서는 온도 폴백이 발동해 무작위 샘플링이 섞임: 같은 파일 2회 인식에서 16개 중 4개가 달랐고, `temperature=0.0`이면 16개 모두 같았음 [확인], 검토 문서 13.5). 그래서 한 번의 값만으로 조건 차이를 말하지 않고, **반복 실행의 범위**나 `temperature=0.0` 고정 결과를 함께 봅니다. 흩어짐은 **구간 수**로도 봅니다.
- 정답에 오류가 있으면 모든 조건의 WER이 올라갑니다. 조건 **사이의 차이**가 더 믿을 만합니다 [추정].

### 8.3 내 관찰 (3줄 이상, 가사 없이)
*아래는 설정 A·B 결과를 보고 정리한 초안입니다. 귀로 확인한 내용(분리 첫인상 등)은 사용자가 덧붙입니다.*

2. **VAD 켬 + 원곡은 가사를 통째로 지웁니다 [확인].** 8구간 중 같은 5구간이 두 설정, 두 모델, 3회 모두 비었습니다. VAD 켬은 보컬에서도 일부 구간을 잘라 먹었습니다(base 보컬 c01 0.05 → 0.45, c08 0.00 → 0.80).
3. **최고 조합은 설정에 따라 달랐습니다 [확인].** 설정 A는 base + VAD 켬 + 보컬(0.494), 설정 B(기본)는 **base + VAD 끔 + 보컬(0.382)** 입니다. 파이프라인은 기본 설정이므로 후자를 따릅니다.
