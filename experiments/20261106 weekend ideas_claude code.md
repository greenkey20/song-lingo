# song-lingo 다음 방향 브레인스토밍 (2026-11-06)

출퇴근길·근무 중에 틈틈이 보려고 짧은 단위로 나눠 둔 **아이디어 목록**입니다. 결정된 것이 아니라 후보이며, 결정되면 검토 문서(주제에 맞는 장)와 계획서에 옮깁니다. 표기: **[일반 지식]** 일반적으로 알려진 내용(확인 필요), **[추정]** 내 추측, **[미확인]** 아직 못 해 본 확인. 난이도 ★(1h 안팎) ★★(반나절) ★★★(며칠).

**현재 일정**: 발표 11-12, 지금은 #52 배포가 우선입니다. 이 문서의 대부분은 **발표 뒤 로드맵**이고, 발표 전에 할 수 있는 것은 7절에 따로 골랐습니다. 노래 가사·음원은 문서에 옮기지 않습니다(직접 쓴 문장과 숫자만).

## 3. 소리의 성질·소리 데이터 특징을 최대한 쓰기

지금 쓰는 소리의 성질은 음량·무음·시간 구간뿐입니다. 소리에는 더 많은 정보가 있고, 그 대부분은 **글(텍스트)로 바꾸면 사라지는 것**입니다. STT/WER은 "무슨 말인가"만 보지만 발음 학습에는 **어떻게 말했나**가 필요합니다.

| 소리의 성질 | 무엇을 알려 주나 | 어떤 연습에 쓰나 | 구현 감 |
|---|---|---|---|
| **음높이 F0 (기본 주파수)** | 억양·성조·멜로디 | 의문문 끝 올림, 일본어 높낮이 악센트, 중국어·태국어·베트남어 성조, 노래 음정 | 1-3의 F0 추출 → 윤곽 선 그래프 2개(TTS vs 나) 겹치기 |
| **지속 시간·리듬** | 장단, 속도, 박자 | 일본어 장음·촉음 길이, 영어 강세 박자, 노래 박자 맞추기 | 음절/단어 경계(`stt.recognize_words` 시간)로 길이 비율 비교 |
| **세기(에너지) 윤곽** | 강세, 강조 | 영어 강세, 문장 억양의 강약 | RMS 프레임 곡선 |
| **스펙트럼 모양(포먼트 F1/F2)** | 모음의 종류 | 모음 구별(a/e/i/o/u, 영어 짧은 모음) | 스펙트럼 피크 → **모음 지도**(F1–F2 평면)에 TTS와 내 모음을 점으로 |
| **고주파 에너지·스펙트럼 무게중심** | 마찰음·파찰음 종류 | s/sh, f, th 같은 자음 구별 | 프레임별 centroid/고주파 비율 |
| **파열 후 숨(기식)·VOT** | 유성/무성·유기음 차이 | 영어 p/t/k vs 한국어 평음·격음·경음 | 짧은 구간의 에너지 폭발 길이 (고급) |
| **조음 속도·쉼** | 유창성 | 끊어 읽기, 머뭇거림 (Azure 유창성/운율과 비교) | 단어 사이 무음 길이 |

### 3-1. 특히 유망한 것 (소리 데이터라서 가능한 것)
1. **억양(F0) 윤곽 겹쳐 보기** — 가장 직관적. 의문문·감정·성조 언어에서 STT 점수는 놓치지만 윤곽에서는 바로 보입니다. Azure 운율 점수는 영어(en-US)만 제공되므로 **다국어 억양 피드백은 우리가 직접 만들 수 있는 거의 유일한 틈**입니다.
2. **보컬 stem으로 노래 멜로디(F0) 뽑기** — Demucs로 분리한 **보컬만**의 음높이를 따라가면 반주에 방해받지 않습니다. 이것이 "분리를 쓰는 이유"를 하나 더 만듭니다: (a) 노래의 음정을 "기준 멜로디"로 삼아 사용자가 따라 부른 음정과 비교(cent 단위), (b) 가사 학습에 멜로디를 같이 쓰면 기억에 도움이 된다는 일반론과 연결 [일반 지식, 효과 크기는 [미확인]].
3. **줄 경계를 보컬 에너지로 정밀화(= #32 줄 단위 보컬 조각)** — STT 구간 시각만 쓰는 지금보다 정확한 시작/끝, 기준 음성으로 "보컬 조각" 제공.
4. **리듬 비교**: 영어는 강세 박자, 일본어는 모라(박) 박자, 프랑스어는 음절 박자라고 흔히 설명하지만 엄밀한 분류는 논쟁 중입니다 [일반 지식]. 우리 데이터로 **음절 시작 간격의 변동**을 언어별로 재 보는 것은 작은 실험 주제입니다.
5. **TTS vs 사람의 차이 시각화**: TTS는 F0·박자가 매우 규칙적입니다 [추정]. 이 차이를 보여 주면 "기계 음성은 기준이지 정답이 아니다"라는 안내를 데이터로 뒷받침합니다.

### 3-2. 주의
- F0 추출은 잡음·무성음에서 틀립니다(옥타브 오류). **참고용 표시와 신뢰도 표기** 필요.
- 개인 식별: 녹음 파일은 저장하지 않는 현재 원칙을 유지하고, 저장은 **윤곽 요약 값**까지만 고려(복원 불가 수준인지 판단 필요) [추정].
- Azure 쪽에서 얻을 수 있는 것: 운율(영어만), 음소 점수(영어만). 나머지는 우리가 소리에서 직접.

| 4-5 | **환경 vs 점수**: `quality.py` 경고(음량·무음·클리핑)와 점수의 상관 — "어떤 환경에서 점수가 낮은가" | 지금도 chips 값이 있음, 기록에 요약 추가 | ★★ |
| 4-6 | **소리 지문 갤러리**: 문장별 스펙트로그램 썸네일을 시도 순서로 나열 | 썸네일 저장 필요(개인정보 판단) | ★★ |
| 4-7 | **WER vs Azure 점수 상관**: 우리 오류율과 Azure 종합의 순위 일치도(Spearman) — 점수의 의미를 스스로 검증 | 두 점수를 같은 시도에 기록 | ★ |
| 4-8 | **학습 요약 문장**: 이번 주 연습 N줄, 개선 M줄, 가장 많이 늘어난 줄 (LLM 없이 규칙으로) | 기록 | ★ |

**추천**: 4-1·4-2·4-7은 기록 항목 몇 개만 추가하면 되고, 발표에서 "점수가 무엇을 말하는가"를 설명하기 좋습니다.

## 5. 모르는 언어(러시아어·태국어·베트남어·중국어 …)를 테스트해야 하나?

**답: 사람 발음 테스트는 어렵지만, "기계끼리 왕복 테스트"는 모르는 언어도 가능합니다. 해 볼 가치는 있고, 범위는 작게 하는 것을 권합니다.**

### 5-1. 현재 지원 범위
`languages.py`의 지원 언어 11개: 영어·일본어·한국어·프랑스어·스페인어·독일어·중국어·이탈리아어·포르투갈어·**러시아어**·스웨덴어. **태국어·베트남어는 아직 없음.** 중국어·러시아어는 목록에는 있지만 화면에서 시험한 적은 없습니다(시험한 것은 영어·일본어·프랑스어).

### 5-2. 왜 테스트가 필요한가 (언어마다 부딪히는 것)
| 언어 | 예상되는 문제 | 소리의 성질 |
|---|---|---|
| 중국어 | 공백 없음 → CER 중심(이미 구현), **간체/번체**, 한자 읽기(병음) 표시 필요 | **성조 4개+경성** [일반 지식] → F0 윤곽 시각화의 최적 데모 |
| 러시아어 | **키릴 문자**(읽기 보조로 로마자 표기), 악센트 위치로 발음이 바뀜 | 강세 모음 길이·세기 |
| 베트남어 | 라틴 문자지만 **성조 부호**가 뜻을 바꿈 → `strip_accents` 금지(프랑스어 엄격 모드와 같은 원칙) | **성조 6개(북부 기준)** [일반 지식] |
| 태국어 | **공백 없음**(CER), 문자 읽기 보조 필요, 성조 5개 [일반 지식] | 성조+장단 모음 |
| 공통 | Azure 발음 평가 지원 로캘 [미확인], `gpt-4o-mini-tts` 지원·품질 [미확인], Whisper 언어별 성능 차이 | |

### 5-3. 제안: "TTS→STT 왕복 스모크 테스트" (모르는 언어도 가능)
```
직접 쓴(또는 LLM이 지은) 문장 3개 / 언어
  → tts.py(TTS)로 소리 생성 → stt.py(Whisper)로 다시 인식 → 정답과 CER
  → 같은 소리로 언어 감지(detect_language)도 시험
```
- 얻는 것: 언어별로 **파이프라인이 끝까지 도는지**(감지·TTS·STT·채점 규칙·화면 글꼴), CER이 비정상으로 높은 언어 목록.
- **못 얻는 것**: 사람이 말했을 때의 성능, 문장이 자연스러운지(내가 모르는 언어라 검증 불가). → **"기계–기계 일관성 확인"** 이라고 명시.
- 비용: 언어 4개 × 문장 3개 = TTS 호출 12번 정도(작음) [추정]. 노래 가사는 쓰지 않고 직접 쓴 문장만.
- 읽기 보조(병음·태국어 로마자·러시아어 translit)는 **새 라이브러리 필요** → 승인 후. 결정적 도구가 필요 없는 범위(채점·인식)부터 시험.

### 5-4. 권장 순서
1. **중국어** — 이미 목록에 있고 성조·CER·병음이 한 번에 나옴. F0 데모 가치 최고.
2. **러시아어** — 목록에 있음. 키릴 정규화/읽기 확인.
3. **베트남어** — 지원 추가(코드 한 줄 수준) + 성조 부호 유지 규칙.
4. **태국어** — 추가 + 공백 없음 처리.
- 발표 전에는 **표 한 장(언어별 왕복 CER·감지 결과·알려진 한계)** 정도로 충분합니다.

## 7. Demucs 뜯어보기 (#35)와 연결

**이슈 #35의 범위**(요약): ① 원곡·보컬·차이 스펙트로그램 비교 ② 대역별 에너지 비율 곡선 ③ 고정 필터(대역통과) vs Demucs 대조(들어 보기 + STT WER) ④ (선택) 4 stem ⑤ (도전) 마스크 시각화, 모델 중간 출력(훅), 논문 읽기.

- **핵심 질문**: 강사님의 "목소리와 악기의 주파수 음역대가 달라서"가 어디까지 맞나? 일반적으로 음역대는 **많이 겹치고** 음색(배음 구조·시간 변화) 패턴이 다르다고 설명됩니다 [일반 지식, 이 이슈의 가설].
- **연결 아이디어**
  - 대역별 비율 곡선(②)을 **음높이 구간별**로(저음~고음) 그리면 3절의 F0/포먼트 개념과 이어짐.
  - 보컬 stem에서 F0 추출 → 3-1의 2번(멜로디 비교)로 확장.
  - 고정 필터 대조(③)는 "그냥 필터로는 왜 안 되나"를 숫자로 보여 주는 **발표용 한 장**.
  - 분리 품질 지표 SDR 설명(정답 stem이 있을 때만 계산 가능, 상업곡에는 없음) [일반 지식] — 우리는 귀 + STT WER로 대신 평가한다는 한계 서술.
  - 처리 시간·메모리(CPU 20초 구간 1~3분)를 서버(Oracle ARM)와 비교(#52 측정과 같이).
- **저작권**: 그림도 곡의 파생물 → `results/`(git 제외)에 두고 커밋 안 함. 발표는 시연 곡 1개 범위에서만.
- 규모: ①~③ 약 1.5~3h [추정], 우선순위 L3.

## 8. 우선순위 제안

### 8-1. 발표(11-12) 전에 할 수 있는 것 (≤ 1h 단위, 배포 #52가 끝난 뒤 여유가 있을 때)
| 순위 | 항목 | 이유 |
|---|---|---|
| 1 | **5-3 다국어 왕복 스모크 테스트 (중국어·러시아어 먼저)** | 코드 거의 없음, "모르는 언어도 돌아가는가"에 바로 답, 표 한 장 |
| 2 | **4-7 + 4-2: 기록에 Azure 4항목·두 점수 같이 저장** → 상관 그림 | 기록 항목만 추가, 점수의 의미 설명 |
| 3 | **1-8 의심 단어 표시**(단어 확률) | 이미 값이 있음, 학습자에게 즉시 유용 |
| 4 | **1-1/1-2/1-4 샘플링·양자화·STFT 창 실험** | 수업 복습 + 슬라이드 소재 |
| 5 | **#35의 ①~③ 중 하나**(스펙트로그램 3종 비교) | 시연 곡 1개로 충분 |

### 8-2. 발표 뒤 로드맵
1. **F0 윤곽 비교**(1-3 → 3절) → 성조 언어로 확장 → 학습 이력(4-3)
2. **간격 반복·빈칸 받아쓰기·역방향 말하기**(2-1·2-2·2-7)
3. **최소 대립쌍 퀴즈**(2-10)
4. **모음 지도(포먼트)**(3절)
5. **보컬 F0로 노래 멜로디 비교**(3-1의 2번)
6. 데이터셋 manifest와 타인 녹음(1-6), 소형 CNN 응용(1-7)

### 8-3. 만들지 않을 것 (현재 방침 재확인)
- Keras 모델을 **제품 STT로 쓰지 않음**(방침). 학습 실험용으로만.
- 발음 "정답 점수"를 우리가 임의로 만들지 않음 — 외부 기준(Azure)과 우리 지표를 **구분해서** 보여 줌.
- 상업 가사를 문서·저장소에 옮기지 않음.

## 9. 결정이 필요한 것 / 열린 질문
1. 다국어 스모크 테스트에서 **언어를 어디까지**(중국어·러시아어만 vs 태국어·베트남어 추가)?
2. 학습 이력에 **윤곽 요약값을 저장**해도 되는가(개인정보 판단: 문장 글은 저장 안 함 원칙과의 균형)?
3. 간격 반복처럼 **기록을 사용자 로컬에 저장**하는 기능을 배포 환경에서 허용할지(세션 임시 저장 원칙과 충돌).
4. 라이브러리 추가 승인: 병음(`pypinyin` 등), 태국어 로마자, 음높이 추출(직접 numpy vs `librosa`), IPA(`phonemizer`+espeak-ng).
5. 발표에서 "소리의 성질을 어떻게 활용했나"를 **무엇으로 보여 줄지**: 소리 모양 그림(현재) + F0 윤곽(추가) 한 장이면 충분한가.
6. 강사님께 여쭤볼 것: 발음 피드백에서 **억양(F0)을 직접 만드는 것**이 Azure 운율(영어만)과 비교해 의미 있는 확장인지.
