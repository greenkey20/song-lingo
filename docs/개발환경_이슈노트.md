# 개발환경·git 이슈 노트

이 프로젝트(song-lingo)에서 **개발환경(Python 환경, 노트북 커널, 마이크), git 작업 중 겪은 문제와 해결책**을 모아 두는 문서입니다. 새 문제가 생기면 "이슈 로그"에 번호를 이어 추가합니다. (학습 저장소의 `ict_innovation_sq_voice_ai/개발환경_이슈노트.md`와 같은 형식입니다.)

판단·옵션 비교는 `프로젝트_안내_및_주제_검토.md`, 하루 작업 기록은 `작업_일지.md`에 두고, 이 문서에는 **"이런 증상이 나오면 이렇게 한다"** 만 적습니다. 표시: [확인] 직접 실행해 확인, [추정] 동작으로 짐작, [일반 지식] 일반적으로 알려진 내용.

## 기본 환경 원칙

- **conda 환경 `voice-ai`(Python 3.11)만 사용합니다.** 경로는 `/opt/anaconda3/envs/voice-ai/bin/python`. `base` 등 다른 환경은 쓰지 않습니다.
- `numpy`는 **1.26.4 고정**입니다(TensorFlow 2.16이 `numpy<2`를 요구). 새 패키지는 설치 전에 `--dry-run`으로 numpy가 바뀌는지 봅니다.
- 노트북 커널이 `voice-ai`인지 확인: `import sys; print(sys.executable)` → `/opt/anaconda3/envs/voice-ai/bin/python`.
- 터미널 명령은 모두 **프로젝트 루트**에서 실행합니다(테스트가 루트의 모듈을 import함).

## 이슈 로그

### 환경·패키지

#### 1. 노트북에서 `.py`나 `.env`를 고쳤는데 반영이 안 됨 (예: `normalize() got an unexpected keyword argument 'unify'`)

- **증상**: 2026-11-03, `scoring.py`에 `unify` 인자를 추가한 뒤 노트북 셀에서 `TypeError: normalize() got an unexpected keyword argument 'unify'`. 이전에는 `.env`의 API 키를 바꿨는데도 같은 401 오류가 났음.
- **원인**: 노트북 커널은 **이미 import한 모듈과 `.env`를 다시 읽지 않습니다.** 메모리에 있는 옛 버전이 계속 쓰입니다 [확인: 재시작 뒤 해결].
- **해결**: 커널 재시작(Restart Kernel) 후 셀을 처음부터 다시 실행. `.py`·`.env`를 고쳤다면 항상 재시작합니다.
- **예방**: 오류 메시지가 "방금 고친 코드와 안 맞는" 내용이면 코드보다 먼저 커널 재시작을 의심합니다.

#### 2. 새 패키지를 깔다가 numpy가 올라갈 위험

- **배경**: 학습 저장소 이슈 노트 #9에서 `ultralytics` 설치가 `numpy`를 2.x로 올려 TensorFlow import가 깨진 적이 있습니다.
- **이 프로젝트의 방식**: 설치 전 `$PY -m pip install <패키지> --dry-run`으로 바뀌는 목록을 보고, numpy가 포함되면 설치하지 않습니다. 2026-11-03 `sounddevice==0.5.6`도 dry-run으로 numpy 불변을 확인한 뒤 설치했습니다 [확인].
- **설치 후 점검**: `$PY -m pip list | grep -i -E "numpy|tensorflow"`, `$PY -m pip check`.

#### 3. `pytest`가 없음

- 이 환경에는 `pytest`가 없습니다. 테스트는 표준 라이브러리 `unittest`로 합니다: `$PY -m unittest discover -s tests -v`.

#### 4. 마이크 녹음(`sounddevice`)이 안 됨 / 권한

- **준비**: `sounddevice==0.5.6` 설치됨(`requirements.txt`). 녹음은 터미널의 `scripts/record_takes.py`로 하고, **Claude는 마이크 권한이 없어 실행하지 않습니다.** 사용자가 직접 실행합니다.
- **macOS 마이크 권한**: 터미널(또는 VS Code)에 마이크 권한이 없으면 소리가 안 들어오거나 오류가 납니다. 시스템 설정 → 개인정보 보호 및 보안 → 마이크에서 사용 중인 앱을 허용합니다 [일반 지식].
- **장치 확인**: `$PY scripts/record_takes.py --devices`. 내장 마이크는 보통 44.1 kHz, 2채널로 잡힙니다 [확인: 2026-11-03 녹음 27건]. 입력 채널이 1개뿐인 장치는 같은 소리를 양쪽에 복사해 스테레오로 저장합니다.
- 사용법 전체는 `연습_문장_데이터_설명.md` 5.1.

#### 5. OpenAI API 키가 적용되지 않거나 과금이 걱정될 때

- 어떤 키가 쓰이는지는 `$PY scripts/check_api_key.py`(값은 가려서 보여 줌). `.env`를 읽으므로 **Claude는 실행하지 않고** 사용자가 `! $PY scripts/check_api_key.py`로 실행합니다.
- 키를 바꾼 뒤에는 커널 재시작(#1).
- 과금이 나는 곳은 TTS 한 곳이고, 캐시(`data/tts_cache/`)에 없는 문장일 때만 호출됩니다. 노트북의 `GENERATE_MISSING_TTS`가 `True`이면 없는 문장을 새로 만들어 과금될 수 있습니다.

#### 14. `pip install demucs`가 `sphn` 빌드 실패로 중단됨 (2026-11-03)

- **증상**: `$PY -m pip install demucs` 끝에 `Failed to build installable wheels for some pyproject.toml based projects` / `sphn`. `--dry-run`에서는 `demucs-4.1.0 einops julius lameenc safetensors sphn`이 설치될 것으로 보였음.
- **원인**: 의존 패키지 `sphn`의 휠을 이 환경(Python 3.11, macOS 13 Intel)에서 받지 못해 소스 빌드로 넘어갔고 실패함 [추정: 휠이 없어서; 빌드 로그 원인은 확인하지 않음]. 설치가 중단되어 환경은 변하지 않았음(numpy 1.26.4, torch 2.2.2 [확인]).
- **해결**: `sphn` 없이 `$PY -m pip install --no-deps demucs`, 이어서 `$PY -m pip install --no-deps einops julius lameenc safetensors`. `demucs.pretrained`·`demucs.apply`·`demucs.audio` import와 `htdemucs` 분리 실행이 됨 [확인]. `sphn`이 필요한 기능이 있는지는 [미확인].
- **알아둘 점**: `--dry-run`이 통과해도 소스 빌드 단계의 실패는 예측하지 못함. `--no-deps`로 깔면 빠진 의존 패키지가 import 때 드러나므로 설치 직후 `import`와 짧은 실행으로 확인한다.

#### 22. Streamlit 앱이 "Connection lost"이고 테마가 하나도 안 먹음: `config.toml`의 글꼴 주소가 둘 이상 (2026-11-05)

- **증상**: 앱 화면은 열리는데 곡을 올리면 "Connection lost", 테마(색·글꼴)가 전혀 적용되지 않음. 브라우저 시크릿 창·Firefox·테마 메뉴를 바꿔도 같음.
- **원인**: `font = "Nunito:<주소>, Noto Sans KR:<주소>, sans-serif"`처럼 **Google Fonts 주소를 둘 이상** 넣으면 서버 로그에 `StreamlitInvalidThemeOptionError: ... contains multiple fonts`가 나고, 세션을 만들지 못해 화면은 열려도 서버와 이어지지 못함 [확인: 서버 로그]. Streamlit은 글꼴 설정 하나에 `family=`가 한 번만 든 주소를 받는다.
- **진단**: 앱을 백그라운드로 띄우고 로그를 읽는다(`streamlit config show`처럼 설정 값만 읽는 확인으로는 이 오류가 안 잡힘). 세션 생성 함수를 직접 불러 보면 재현된다: `from streamlit.runtime.app_session import _populate_theme_msg` 후 `_populate_theme_msg(CustomThemeConfig())`.
- **해결**: `font`(본문, Noto Sans KR)와 `headingFont`(제목, Nunito)로 나눠 각각 주소 하나만 둠. `tests/test_theme_config.py`가 재발을 막는다.

#### 23. `! streamlit run ...`을 쳤는데 아무 일도 안 일어남 (2026-11-05)

- **증상**: Claude Code 입력창에서 `!`로 서버 명령을 실행했는데 출력이 없고 화면도 안 열림.
- **원인**: 서버는 **끝나지 않는 명령**이라, 끝나야 결과를 보여 주는 `!` 실행에서는 아무 출력이 안 보인다 [추정]. 그 사이 서버가 떠 있었는지는 포트(`curl localhost:8501/_stcore/health` → `ok`)로 확인한다.
- **해결**: Claude가 백그라운드로 서버를 띄운다(`run_in_background`) 또는 사용자가 **별도 터미널 창**에서 직접 실행한다. 확인은 브라우저에서 `http://localhost:8501`. 서버를 끌 때는 `pkill -f "streamlit run app/streamlit_app.py"`.
- **참고**: 코드를 고친 뒤에는 브라우저의 Rerun(`R`)으로 반영되지만, `.streamlit/config.toml`을 고치면 **서버를 다시 띄워야** 한다.

#### 24. 웹 앱의 보컬 분리는 `voice-ai`의 파이썬으로 별도 프로세스에서 돌림 (2026-11-05)

- **질문**: `demucs`를 `voice-ai`에 이미 설치했는데 왜 앱 환경에 또 설치해야 하나, `voice-ai`에서 돌린 결과만 받으면 안 되나.
- **답**: 받으면 된다. 앱(Streamlit 전용 환경)은 `import`를 자기 프로세스 안에서 하므로 그 환경에 demucs·torch가 없으면 못 쓴다. 대신 `separate.separate_clip_subprocess`가 `scripts/separate_worker.py`를 **다른 파이썬 프로세스**로 실행하고 결과 wav 파일만 받는다.
- **쓸 파이썬 정하기**: 인자 > 환경변수 `SONGLINGO_SEPARATE_PYTHON` > 지금 파이썬(`sys.executable`). 내 컴퓨터: `SONGLINGO_SEPARATE_PYTHON=/opt/anaconda3/envs/voice-ai/bin/python`(`.env`에 적거나 서버를 띄울 때 앞에 붙임, `.env.example` 참고). 배포 서버: 설정 없이 그 환경 자체의 파이썬을 쓰므로 거기에 demucs를 설치해야 한다.
- **같은 프로세스에서 안 돌리는 이유**: faster-whisper와 torch를 한 프로세스에서 불러면 종료 코드 139로 죽음(#15). 앱은 인식에 faster-whisper를 쓰므로 설령 앱 환경에 demucs를 깔아도 분리는 별도 프로세스가 안전하다.
- **확인**: 합성 신호 6초 구간을 앱 쪽 함수로 `voice-ai` 파이썬에 시켜 보컬 wav가 만들어짐(작업 시간 78.7초, 모델을 처음 읽는 시간이 섞여 있음 **[추정]**). 실제 곡의 인식·재생은 사용자가 화면에서 확인.

#### 25. 도메인·네임서버·Cloudflare·터널: 개념과 우리 구성 (2026-11-07, 이슈 #52)

배포 주소(`songlingo.kr`)를 만들면서 헷갈린 용어와 **누가 무슨 일을 하는지**를 정리합니다. 표시: [확인] 직접 확인, [추정] 짐작, [일반 지식] 일반적으로 알려진 내용(확인 필요).

**한 장 요약**
```text
도메인 등록업체(hosting.co.kr)  ─ "이 도메인의 DNS는 어느 네임서버가 맡나"를 기록 ─▶  네임서버(Cloudflare)
                                                                                      │  DNS 기록 + 프록시(HTTPS·보호)
브라우저 ─https://songlingo.kr─▶ Cloudflare ◀─서버가 먼저 연결(cloudflared 터널)─ Oracle 서버 127.0.0.1:8501 (Streamlit)
```

| 용어 | 뜻 | 우리 구성에서 |
|---|---|---|
| **도메인 등록업체(registrar)** | 도메인 이름을 **내 이름으로 등록해 두는 곳**. 등록 정보와 "이 도메인의 네임서버는 어디인가"를 관리합니다 [일반 지식] | `hosting.co.kr`(국내 업체). `songlingo.kr`은 처음에 이곳의 네임서버(`ns1~4.hosting.co.kr`)를 썼음 [확인: dig NS] |
| **네임서버(NS, name server)** | 도메인의 **DNS 기록(주소록)을 갖고 대답해 주는 서버**. 도메인마다 "내 DNS는 이 네임서버가 맡는다"가 지정되어 있습니다 [일반 지식] | 업체 화면에서 `songlingo.kr`의 네임서버를 **Cloudflare가 준 2개**로 바꿈 → 이제 DNS 기록은 **Cloudflare에서 관리**. 전파에 몇 분~몇 시간 걸림, 완료되면 Cloudflare가 "Active"로 알려 줌 [확인] |
| **DNS 기록** | 이름 → 주소 연결표. **A** = 이름 → IP 주소, **CNAME** = 이름 → 다른 이름의 별명 | 예전에는 A 기록 2개가 있었고 등록업체의 기본 페이지 IP로 보임 [확인: dig, 용도는 추정](아래 #26의 원인 후보) |
| **Cloudflare의 역할** | ① **DNS 호스팅**(위 기록을 대답해 줌) ② **프록시**: 방문자는 Cloudflare에 접속하고 Cloudflare가 서버로 대신 연결(주황 구름 = Proxied, 회색 = DNS only) ③ **HTTPS 종단**: 인증서를 Cloudflare가 처리 ④ **보호**(DDoS 완화, 속도 제한 등) ⑤ **터널·Zero Trust** [일반 지식] | 무료(Free) 플랜. `songlingo.kr` Active 확인 [확인] |
| **오리진(origin)** | Cloudflare 뒤에 있는 **진짜 서버** | Oracle 서버의 Streamlit(`127.0.0.1:8501`) |
| **Cloudflare Tunnel(`cloudflared`)** | 서버에 작은 프로그램을 깔면 **서버가 Cloudflare로 나가는 연결**을 맺고, Cloudflare가 그 연결로 요청을 전달하는 방식. **서버의 포트를 열 필요가 없고** 서버 IP가 드러나지 않음 [일반 지식] | `songlingo.kr`에 사용. 터널 대상은 `http://localhost:8501` |
| **SSL 모드(Flexible / Full)** | Cloudflare ↔ 오리진 구간을 HTTP로 할지 HTTPS로 할지. Flexible은 방문자↔Cloudflare만 HTTPS [일반 지식] | 터널에서는 신경 쓰지 않아도 됨 |

**같은 서버의 두 사이트는 연결 방식이 다릅니다** (이 차이가 처음에 낯설었던 이유)

| | `innerorbit.kr` | `songlingo.kr` |
|---|---|---|
| DNS | Cloudflare [확인: NS가 `*.ns.cloudflare.com`, 응답 헤더 `server: cloudflare`] | Cloudflare(11-07에 이전) |
| 서버까지 오는 길 | Cloudflare가 **서버 IP의 80번 포트로 직접 접속**(Proxied A 기록, 서버는 HTTP만) [추정: 서버가 80을 `0.0.0.0`에 열고 있고 `cloudflared`가 없음 [확인], DNS 탭에서 A 기록인지 확인 필요] | **터널**(서버가 먼저 연결) |
| 서버의 80번 | inner-orbit의 Nginx 컨테이너가 사용 [확인: `ss`] | 쓰지 않음(충돌 없음) |
| 서버에 필요한 프로그램 | Docker(compose) | `cloudflared`(systemd 서비스) |
| 방화벽 | 80번 열림 | **열 필요 없음** |

**왜 song-lingo는 터널로 했나**: 80번을 inner-orbit이 이미 쓰고 있어서 같은 방식(A 기록 + 80번)을 쓰려면 포트와 방화벽(Oracle 보안 목록·iptables)을 건드려야 하고 inner-orbit의 `docker-compose`(CI/CD로 자동 재배포됨)에 영향을 줄 수 있어서입니다. 터널은 서버에서 **밖으로 나가는 연결**이라 그런 변경이 필요 없습니다. HTTPS가 있어야 브라우저 마이크(`st.audio_input`)가 동작합니다(localhost 제외).

**http와 https, 그리고 왜 터널의 서비스 URL은 `http://localhost:8501`인데 주소창에는 `https://songlingo.kr`인가**

| 용어 | 뜻 |
|---|---|
| **HTTP** | 브라우저와 서버가 **요청과 응답을 주고받는 규칙**. 내용이 **암호화되지 않은 글자 그대로** 오가서 중간 사람이 볼 수 있음. 기본 포트 80 [일반 지식] |
| **HTTPS** | **HTTP를 TLS(암호화 방식)로 감싼 것**. 같은 HTTP 메시지를 암호화해서 보내고, 서버의 **인증서**로 "이 주소의 진짜 서버가 맞다"를 확인함. 주소창의 자물쇠. 기본 포트 443 [일반 지식] |
| **TLS와 인증서** | TLS = 암호화 통신 규칙. 인증서 = 인증 기관(CA)이 "이 도메인의 키는 이것"이라고 보증한 증명서. Cloudflare가 `songlingo.kr`용 인증서를 **자동으로 발급·갱신**해 줌(Universal SSL) [일반 지식] |
| **localhost / 127.0.0.1** | "**이 컴퓨터 자신**"을 가리키는 주소(loopback). 서버에서 `localhost`는 그 서버 자신이고, 이 연결은 **서버 밖으로 나가지 않음** |
| **포트(8501)** | 한 컴퓨터 안에서 프로그램을 구분하는 번호. 80(HTTP), 443(HTTPS)은 기본값이라 주소창에 안 보이고, 8501은 Streamlit이 쓰는 번호일 뿐 |
| **웹소켓(ws/wss)** | Streamlit이 화면을 실시간으로 갱신하려고 쓰는 연결. 페이지가 HTTPS이면 자동으로 암호화된 `wss`를 씀 |

**길이 세 구간으로 나뉩니다** — 두 주소가 다른 이유

```text
① 브라우저 ──HTTPS(암호화, 443)──▶ Cloudflare            주소창: https://songlingo.kr  (인증서는 Cloudflare가 처리)
② Cloudflare ══터널(서버가 먼저 맺은, 암호화된 연결)══▶ cloudflared   (Cloudflare가 알아서 하는 구간)
③ cloudflared ──HTTP(평문)──▶ Streamlit                   터널의 서비스 URL: http://localhost:8501  (서버 안에서만)
```

- **서비스 URL(`http://localhost:8501`)은 "③번: 서버 안에서 cloudflared가 앱에게 전달할 주소"** 입니다. 방문자는 이 주소를 보지 않습니다. `localhost`이므로 **서버를 벗어나지 않아서** 암호화가 필요 없고, Streamlit은 인증서 없이 HTTP만 하도록 띄웠습니다(`--server.address 127.0.0.1`). 그래서 여기에는 `https://`가 아니라 **`http://`** 를 씁니다. `https://localhost:8501`로 적으면 Streamlit에 인증서가 없어 연결이 실패하는 것이 일반적입니다 [일반 지식].
- **브라우저 주소창의 `https://songlingo.kr`은 "①번: 방문자와 Cloudflare 사이"** 입니다. 인터넷을 지나는 구간이라 암호화해야 하고, **HTTPS를 처리하는 곳(인증서가 있는 곳)이 Cloudflare**입니다. 우리 서버(Streamlit)는 HTTPS를 직접 하지 않습니다. 이처럼 암호화를 중간에서 풀어 주는 것을 "HTTPS 종단(termination)"이라고 합니다 [일반 지식].
- 그래서 **한 번의 접속이 https(바깥)와 http(서버 안)를 모두 거칩니다.** 두 주소가 다른 것은 모순이 아니라 **구간이 달라서**입니다.

**innerorbit.kr과 비교** [추정: 방식]: ①은 HTTPS(Cloudflare), ②는 터널이 아니라 Cloudflare가 서버 IP의 **80번 포트로 HTTP로 직접 접속**합니다(인터넷을 지나는 구간이 암호화되지 않음). 서버가 `https`를 받지 않고(443 미사용) 80만 연 것과 맞습니다 [확인: `ss`]. http://innerorbit.kr은 https로 **301 이동**됨 [확인: curl]. 터널은 ②가 암호화되어 있어서 이 점이 낫습니다.

**왜 HTTPS여야 하나 — 마이크**: 브라우저는 마이크·카메라 같은 민감한 기능을 **"보안 컨텍스트"에서만** 허용합니다. 보안 컨텍스트는 **HTTPS 주소 또는 `localhost`** 입니다 [일반 지식]. 그래서
- `ssh -L`로 연 `http://localhost:8501`은 `localhost`라서 마이크가 **됨**,
- `http://서버IP:8501`처럼 HTTP로 공개 주소를 쓰면 **안 됨**,
- `https://songlingo.kr`은 HTTPS라서 **됨**(Streamlit의 `st.audio_input`).

**흔한 실수**: ① 터널의 Service Type을 HTTPS로 고르거나 URL에 `https://localhost:8501`을 씀 → 연결 실패(502 계열). ② 서비스 URL에 서버 공인 IP를 씀 → 터널의 장점(포트 닫기·IP 숨기기)이 사라짐. ③ 주소에 `:8501`을 붙여 `https://songlingo.kr:8501`로 접속하려 함 → Cloudflare는 정해진 포트만 받으므로 안 됨 [일반 지식]. 방문자는 항상 `https://songlingo.kr`만 쓴다.

**확인 명령 (내 컴퓨터에서)**
```bash
dig +short NS songlingo.kr              # 어느 네임서버가 맡고 있나 (Cloudflare 이름이 나오면 이전 완료)
dig +short A songlingo.kr               # Proxied이면 Cloudflare의 IP가 나옴(서버 IP가 아님)
curl -sI https://songlingo.kr | head -5 # server: cloudflare, 비밀번호 화면이면 200
```
서버에서는 `ps aux | grep cloudflared`(터널이 있나)와 `systemctl status cloudflared --no-pager | head -6`.

**순서**: ① 도메인 구입(`hosting.co.kr`) → ② Cloudflare에 사이트 추가(Free) → ③ 업체 화면에서 네임서버를 Cloudflare 것으로 변경 → ④ Active 대기 → ⑤ 옛 DNS 기록(A 등) 삭제 → ⑥ Zero Trust에서 터널 생성, 서버에 `cloudflared` 설치 → ⑦ Public hostname에 `songlingo.kr` → `HTTP` → `localhost:8501` 등록 → ⑧ 시크릿 창에서 접속 시험 → ⑨ `cloudflared`를 서비스로 등록(#29).

#### 26. Cloudflare 522 "Connection timed out" — 터널을 만들었는데 오리진 연결 시간 초과 (2026-11-07, 이슈 #52)

- **증상**: `https://songlingo.kr`이 Cloudflare 오류 페이지(**522**, "Cloudflare와 오리진 서버 사이의 최초 연결이 시간 초과")를 보여 줌. Browser·Cloudflare는 Working, Host만 Error [확인: 오류 페이지].
- **원인 [추정]**: 터널이 아니라 **옛 A 기록**(Cloudflare가 도메인을 추가할 때 가져온 등록업체 기본 IP)이 남아 있어서, Cloudflare가 그 IP로 접속하려다 시간 초과. 터널로 연결됐다면 522 대신 다른 오류가 나는 것이 일반적 [일반 지식].

- **상태**: 적용 중, 결과는 확인 후 갱신.
- **알아둘 점**: 522는 "오리진에 닿지 못함", 502/1033 계열은 "터널이 안 붙었거나 대상이 응답하지 않음"으로 구분해서 본다 [일반 지식].

#### 28. systemd 서비스 파일(`song-lingo.service`): 무엇이고, 붙여넣기로 파일이 오염됐을 때 (2026-11-07, 이슈 #52)

- **무엇인가**: 서버를 관리하는 시스템(systemd)에게 **"이 프로그램을 켜 두고, 죽으면 다시 살리고, 부팅 때 자동으로 시작해"** 라고 알려 주는 설정 파일. 위치 `/etc/systemd/system/song-lingo.service`. `[Service]`의 `ExecStart`가 실행 명령, `Restart=on-failure`가 비정상 종료 시 재시작, `MemoryMax=8G`가 메모리 상한(같은 서버의 inner-orbit 보호), `[Install]`의 `WantedBy=multi-user.target`이 부팅 시 자동 시작. `.env`는 앱이 직접 읽으므로 `EnvironmentFile`은 불필요. `Environment=SONGLINGO_SEPARATE_PYTHON=…`만 지정.
- **증상**: `systemctl status`에 `Loaded: … disabled`와 `Missing '=', ignoring line`, `Unknown key name '- Restart' in section 'Install'`. 앱은 돌고 있었지만 **부팅 때 자동 시작이 안 되고** `Restart` 등이 무시됨.
- **원인**: `nano`에 붙여넣을 때 문서 서식(`- ` 불릿)과 중복 내용이 섞여 파일이 20줄을 넘고 `[Install]`이 깨짐 [확인: 로그의 줄 번호와 키 이름].
- **해결**: `sudo tee … <<'EOF'` 로 **내용 전체를 한 번에 덮어씀**(편집기 없이 붙여넣기 문제를 피함) 후 `sudo systemd-analyze verify …`(출력이 없으면 문법 정상), `sudo systemctl daemon-reload`, `sudo systemctl enable song-lingo`, `sudo systemctl restart song-lingo`. `is-enabled`가 `enabled`, `systemctl show song-lingo -p Restart -p MemoryMax -p Environment`가 값을 보이면 성공 [확인].
- **무시해도 되는 경고**: `systemd-analyze verify`에서 `unified-monitoring-agent_*.service … is marked executable`은 Oracle 이미지의 다른 서비스 파일 권한 경고로 우리와 무관 [확인].
- **자주 쓰는 명령**: `systemctl status song-lingo --no-pager`, `journalctl -u song-lingo -n 50 --no-pager`(로그), `sudo systemctl restart song-lingo`(코드·`.env` 바꾼 뒤), `sudo systemctl stop song-lingo`.

  1. **커널 재시작 후 ⑥만 실행**: ①(설정) → ②(CLIPS) → ⑤(정답 상태) → ⑥ 순서로 실행하고 ③b는 실행하지 않는다. 분리는 이미 끝나 파일에 있으므로 다시 할 필요가 없다. (분리를 더 하려면 다시 재시작: 같은 커널에서 두 가지를 쓰지 않는다.)
  2. **분리를 별도 프로세스로 실행**(근본 해결, 적용함): 노트북 ③b가 `scripts/separate_clip.py --separate-only`를 `subprocess`로 부르게 바꿨다. 6초 임시 구간으로 확인했고 [확인] 실행 뒤 커널의 `sys.modules`에 `torch`·`demucs`가 없었다. 대신 구간마다 새 프로세스라 torch 불러오기와 모델 읽기(수 초)가 매번 든다. 이 방법을 적용한 노트북에서는 1번(재시작)이 필요 없다.
  3. **쓰지 말 것**: 환경 변수 `KMP_DUPLICATE_LIB_OK=TRUE`로 오류를 끄는 방법. 오류 메시지 자체가 "충돌하거나 **조용히 틀린 결과**를 낼 수 있다"고 경고하며, 이 프로젝트는 측정값을 비교하는 실험이라 조용한 오류가 가장 위험하다.
- **알아둘 점**: 순서가 반대(Whisper → 분리)여도 같은 충돌이 날 것으로 보임 [추정]. 터미널 스크립트는 프로세스가 따로라 문제없음.
- **같은 원인의 다른 모습 [확인, 11-04]**: 한 파이썬 스크립트에서 `faster-whisper`를 불러온 뒤 Demucs를 불러도 같은 충돌이 나는데, 오류 메시지 없이 **종료 코드 139(segfault)** 로 조용히 죽을 수 있습니다(앞선 `OMP: Error #15` 때는 134). 출력이 없고 종료 코드만 이상하면 이 충돌을 의심하고 **둘을 별도 프로세스로** 나눕니다.

  ```bash
  shasum practice.ipynb <백업 파일>                                    #    해시가 같은지 확인
  git restore practice.ipynb                                           # 2) 작업 사본을 커밋 상태로
  git checkout main && git pull                                        # 3) 전환·갱신
  cp <백업 파일> practice.ipynb                                        # 4) 원본 복원 → 다시 M 상태(정상)
  ```
- **주의**: `git restore`는 로컬 변경을 버리므로 **반드시 1)의 백업과 해시 확인 뒤에** 합니다. `git stash`도 가능하지만 노트북 JSON이 커서 백업 파일 방식이 더 눈에 보입니다 [추정].
- 노트북을 VS Code에서 열어 두었다면 *File → Reload Notebook from Disk*.

#### 9. 머지 후 `git pull`이 "Your configuration specifies to merge with the ref 'refs/heads/feat/...' ... no such ref was fetched"

- **증상**: `main` 전환이 막힌 상태(#8)에서 `git pull`을 하면 `feat/…` 브랜치의 업스트림을 찾지 못한다는 메시지. 동시에 `origin/main`은 정상으로 가져옴(`85f5038..cc23a35`).
- **원인**: 머지된 뒤 **원격의 작업 브랜치가 지워졌습니다**(`git ls-remote --heads origin`에 `main`만 있음 [확인]). 지워진 이유(저장소의 "머지 후 브랜치 자동 삭제" 설정인지)는 확인하지 않았습니다 [미확인]. 로컬 브랜치의 업스트림 설정만 남아 있어 나온 메시지입니다.
- **해결**: 오류가 아니라 안내입니다. `main`으로 전환해서 pull하면 됩니다(#8). 로컬 브랜치는 필요 없으면 `git branch -d feat/recorder-normalization`, 남아 있는 원격 추적 참조는 `git fetch --prune`으로 정리합니다.

#### 10. `git add -A` / `git add .` 금지 — 파일을 하나씩 추가

- **이유**: 이 저장소는 공개이고, 작업 폴더에는 내 녹음(`data/`), 결과(`results/`), 모델(`models/`), `.env`처럼 올리면 안 되는 것이 있습니다(대부분 `.gitignore`로 막혀 있지만, 새 파일 이름이 우회될 수 있음).
- **방법**: `git add <파일>`을 하나씩, 매번 `git status`로 확인. 커밋 전 `git ls-files data results models .env`가 비어 있는지 봅니다(2026-11-03 [확인]).

#### 11. 문서에 내 컴퓨터의 절대 경로가 들어감

- **증상**: 설명 문서에 `cd /Users/<계정>/…`처럼 홈 폴더 경로가 적힘 → 공개 저장소에 계정명이 노출.
- **해결**: `cd <song-lingo 프로젝트 폴더>`처럼 자리표시자로 씁니다. 커밋 전 `git diff --cached | grep -n "/Users/"`로 확인합니다.

#### 12. 커밋·이슈 연결 규칙 (헷갈릴 때)

- 메시지에 **`Refs #N`** 만 씁니다. `Closes #N`을 쓰면 머지 때 이슈가 자동으로 닫히는데, **이슈를 닫는 것은 사용자의 판단**입니다(2026-11-03 PR #30에서 Refs만 써서 이슈 #3·#10·#25·#29가 열려 있는 상태로 머지됨 [확인]).
- 보드(GitHub Projects)는 `gh project`가 없어 `gh api graphql`로 바꿉니다(ID는 `CLAUDE.md`).

#### 18. `gh pr edit`이 "Projects (classic) is being deprecated" 오류를 내고 본문이 안 바뀜 (2026-11-03)

- **증상 [확인]**: `gh pr edit 33 --body-file …`의 출력이 `GraphQL: Projects (classic) is being deprecated … (repository.pullRequest.projectCards)`로 끝났고, 다시 읽어 보니 **본문이 바뀌지 않았습니다.** 오류가 경고처럼 보여서 수정이 실패한 줄 모르기 쉽습니다.
- **원인 [추정]**: `gh`가 PR 정보를 읽을 때 폐기된 Projects(classic) 필드(`projectCards`)까지 요청해서 실패하는 것으로 보입니다.
- **해결 [확인]**: REST로 직접 고칩니다.
  ```bash
  gh api repos/<소유자>/<저장소>/pulls/<번호> --jq .body > body.md      # 현재 본문 읽기
  gh api -X PATCH repos/<소유자>/<저장소>/pulls/<번호> -F body=@body.md   # 수정
  gh api repos/<소유자>/<저장소>/pulls/<번호> --jq .body                  # 반드시 다시 읽어 확인
  ```
- **습관**: 수정한 뒤에는 항상 **다시 읽어 바뀌었는지** 확인합니다(이슈·PR 본문, 라벨, 보드 값 모두).

#### 19. 이미 push한 PR 브랜치에서 주제가 다른 커밋 하나만 `main`으로 빼기 (2026-11-03)

- **상황**: PR 브랜치에 주제가 다른 커밋(`practice.ipynb` 문서)이 섞였고, 로컬 작업 트리에는 출력이 남은 노트북 수정(`M`)이 있었습니다. 이 상태로 `git checkout main`·`rebase`를 하면 "local changes would be overwritten"으로 막힙니다(#8).
- **왜 빼나**: 같은 파일을 고치는 두 PR이 생기면 머지 때 충돌합니다(이 경우 `practice.ipynb`를 #34가 또 고칠 예정이었음).
- **절차 [확인: 2026-11-03에 수행]**
  1. 로컬 노트북을 백업하고 해시를 기록합니다: `cp … /tmp/nb_backup/`, `shasum …`.
  2. **작업 트리를 건드리지 않도록 별도 worktree에서** `main` 위에 옮깁니다.
     ```bash
     git worktree add /tmp/wt-docs -b <임시브랜치> origin/main
     cd /tmp/wt-docs && git cherry-pick <커밋>     # 출력 검사(scan_outputs) 후
     git push origin HEAD:main                       # 문서라서 main 직접 반영(프로젝트 합의)
     ```
  3. 정리: `git worktree remove /tmp/wt-docs`, `git branch -D <임시브랜치>`.
  4. 원래 브랜치를 새 `main` 위로 다시 쌓습니다: `git rebase --autostash origin/main`. **같은 변경이 이미 `main`에 있으면 git이 그 커밋을 자동으로 건너뜁니다**(`skipped previously applied commit`). 끝나면 로컬 수정이 자동으로 복원됩니다.
  5. 해시 비교로 로컬 노트북이 백업과 같은지, 테스트가 통과하는지 확인하고 `git push --force-with-lease origin <브랜치>`로 올립니다. `--force-with-lease`는 원격이 내가 아는 상태일 때만 덮어써서 `--force`보다 안전합니다.
  6. 로컬 `main`은 `git fetch origin main:main`으로 체크아웃 없이 따라잡습니다.
- **주의**: 강제 push는 협업자가 없을 때만 합니다. draft PR은 push하면 자동으로 갱신됩니다. `git stash`(맨 명령)는 다른 작업과 공유되므로 `--autostash`나 임시 커밋을 씁니다.

#### 31. 아이폰 Safari "홈 화면에 추가"는 PWA가 아님 — Streamlit은 기본적으로 PWA가 아니다 (2026-11-07, 이슈 #52)

- **질문**: Safari에서 `https://songlingo.kr`을 열고 "홈 화면에 추가"하면 PWA로 열리나?
- **PWA(Progressive Web App)란**: 웹사이트를 **앱처럼** 쓰게 하는 기술 묶음. 보통 ① **웹 앱 매니페스트**(`manifest.json`: 이름·아이콘·`display: standalone`) ② **서비스 워커**(오프라인·캐시)를 갖추고, HTTPS여야 합니다 [일반 지식].
- **확인한 것**: 이 앱이 쓰는 Streamlit 1.66.1의 `static/index.html`에는 **`<link rel="manifest">`도 `apple-touch-icon`도 `apple-mobile-web-app-*` 메타도 없고 `shortcut icon`만 있습니다.** `static/manifest.json`은 웹 앱 매니페스트가 아니라 **빌드 자산 목록**입니다 [확인: 파일 열어 봄]. 따라서 **기본 상태에서는 PWA가 아닙니다.**
- **"홈 화면에 추가"를 하면**: 홈 화면에 **바로가기 아이콘**이 생깁니다. 아이콘은 `apple-touch-icon`이 없어서 페이지 화면을 캡처한 그림이나 글자로 나올 수 있고 [일반 지식], 우리가 넣은 `icon.png`가 쓰이는 것은 아닐 가능성이 큽니다 [추정]. 열었을 때 주소창 없는 전체 화면으로 여는 옵션이 iOS 17 이상에는 있다고 알려져 있지만 [일반 지식, iOS 버전별 동작은 확인 필요], 이것은 **PWA의 기능(오프라인·푸시)** 이 아니라 **주소창만 숨긴 웹페이지**입니다.
- **주의(발표용)**: ① 홈 화면 앱이든 Safari 탭이든 **iOS는 백그라운드로 가면 페이지를 비울 수 있어서** 돌아오면 Streamlit 세션이 새로 만들어지고 입력·결과·비밀번호 인증이 초기화됩니다 [일반 지식, 실제 동작 확인 필요]. ② **마이크(`st.audio_input`)는 iPhone Safari에서 HTTPS로 되는지 직접 시험**해야 합니다 [미확인]. 홈 화면 앱 모드의 마이크 동작은 따로 확인이 필요합니다 [미확인]. ③ 파일 업로드 형식(wma 등)은 휴대폰 파일 선택기에서 다를 수 있습니다 [미확인].
- **진짜 PWA처럼 만들고 싶다면(선택, 발표 뒤)**: Streamlit의 정적 파일 제공(`--server.enableStaticServing true`, `static/` 폴더)으로 `manifest.json`과 아이콘을 내보내고, 페이지의 `<head>`에 `<link rel="manifest">`와 `<link rel="apple-touch-icon">`을 넣어야 합니다. Streamlit은 `<head>`를 직접 고치는 방법을 제공하지 않아서 자바스크립트로 삽입하는 우회가 필요하고 동작은 확인이 필요합니다 [일반 지식, 미확인]. 서비스 워커는 Streamlit 구조상 쉽지 않습니다. **이번 발표에는 필요 없음.**
- **권하는 시험(발표 전)**: iPhone Safari에서 ① `https://songlingo.kr` 열기 → ② 비밀번호 → ③ 내 문장에서 마이크 녹음·채점 → ④ 내 노래 파일 올리기 → ⑤ (원하면) 홈 화면에 추가 → 열기. 결과를 이 항목에 적는다.

### 서버·DB (2026-11-08, 이슈 #63~#75)

#### 32. 서버에서 `git pull`이 "untracked working tree files would be overwritten"로 막힘
- **증상**: 서버 `~/song-lingo`에서 `git pull`이 9커밋 뒤처진 상태라 `storage.py`·`migrations/`가 없었고, 서버에 손으로 만든 `docker-compose.db.yml`(untracked)이 이번 PR에 같은 이름으로 들어와 충돌할 상황.
- **해결** [확인]: `mv docker-compose.db.yml docker-compose.db.yml.server-bak` → `git pull origin main` → `diff`로 비교. 이미 떠 있는 DB 컨테이너는 compose 파일이 없어도 계속 돈다. 서버 `.env.bak-*` 파일은 비밀번호가 들어 있으니 git에 올리지 않는다.

#### 33. 코드를 고쳤는데 `AttributeError: module 'web_song' has no attribute 'restore_lines'`
- **원인**: Streamlit은 `app/` 스크립트는 다시 읽지만 **루트의 `.py` 모듈(`web_song.py` 등)은 이미 import한 것을 메모리에 들고 있다.** 서버(또는 로컬 8502)를 코드 수정 전에 띄웠다면 옛 모듈이다.
- **해결** [확인]: 루트 모듈을 고치면 서버·로컬 모두 앱을 재시작한다(`sudo systemctl restart song-lingo`, 로컬은 서버 종료 후 재실행). 포트가 이미 사용 중이면(`Port 8502 is not available`) `lsof -nP -iTCP:8502 -sTCP:LISTEN`으로 옛 프로세스를 찾아 종료.

#### 34. 서버 시간이 한국 시간과 9시간 다름
- **증상**: `systemctl status`에 `Sat 2026-11-07 19:29 UTC`, 사용자는 11/8 04:29. 같은 순간이다(UTC+9).
- **결정**: 서버는 UTC로 둔다. DB `timestamptz`는 영향이 없고 기록 시각은 코드에서 `Asia/Seoul`로 변환한다(`practice_log.SEOUL`). 서버 시간대 변경(`sudo timedatectl set-timezone Asia/Seoul` + 서비스 재시작)은 같은 서버의 inner-orbit 영향을 확인한 뒤에만(검토 문서 16.17 12절).

#### 35. 내 문장에 같은 줄이 두 번 나오면 `StreamlitDuplicateElementKey: ... key='lyr_ans_…'`
- **원인**: 줄마다의 위젯 열쇠를 줄 내용 해시로 만들어서, 반복되는 후렴 등 같은 글이 있으면 열쇠가 겹친다.
- **해결** [확인]: `web_practice.line_keys`가 반복된 줄에 `_1`, `_2`를 붙인다(첫 줄 열쇠는 그대로). 회귀 시험: 단위 + AppTest(반복 줄 → "언어 알아보기").

#### 36. DB 테스트에서 "고친 줄의 `updated_at`이 이전보다 커야 한다"가 실패
- **원인**: PostgreSQL `now()`는 **트랜잭션 시작 시각**이라 한 `with connect()` 블록(트랜잭션) 안에서는 저장을 두 번 해도 같은 값이다. 앱은 저장마다 별도 트랜잭션이라 실제 문제가 아니다.
- **해결** [확인]: 시험에서 저장마다 연결 블록을 나눈다.

#### 37. 마이그레이션을 추가했더니 옛 마이그레이션 시험이 깨짐
- **증상**: `storage.migrate()`가 `["002…"]`만 돌려준다고 기대했는데 `003`이 생겨 `["002…","003…"]`.
- **해결** [확인]: 시험은 "내가 보려는 파일이 첫 항목인가"만 확인하고 이후 마이그레이션이 늘어도 깨지지 않게 한다.

#### 38. 따라읽기 기록만 DB에 안 남음 (저장 실패 알림만 잠깐 보임)
- **원인**: `stt.settings()`가 **dict**인데 `attempts.stt`(TEXT)에 넣어 INSERT가 실패했다. 받아쓰기·Azure는 `stt`가 비어 있어 통과했다.
- **해결** [확인]: 열을 JSONB `stt_settings`로 바꾸고 dict를 그대로 저장(2단계 전 `stt_label`로 임시 해결 후 제거). 회귀 시험: `tests/test_storage.py::Practices`(dict가 JSONB로 저장·복원됨).
