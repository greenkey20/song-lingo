# 작업 일지 (song-lingo)

이 문서는 하루 작업을 짧게 남기는 일지입니다. 사용자가 Notion 일일 기록에 복사해 쓰고, 강사님과의 면담 때 보는 용도입니다. 양식은 계획서 9장의 일일 기록(날짜 · 한 일 · 막힌 점 · 내일 할 일 · 질문)을 따르고, **면담이 있는 날은 전날 밤에 '강사님께 말씀드릴 것(브리핑)'을 미리 적어 둡니다**(면담 뒤에는 결정 사항 3줄을 채웁니다). 판단의 근거와 옵션 비교는 `프로젝트_안내_및_주제_검토.md`에 있고, 이 문서는 "무엇을 했고 각 파일이 무엇인지"만 적습니다.

> **AI가 쓴 코드를 이해하는 법**: 아래 파일 표의 **"수업과의 관계"** 열에서 '수업 코드 재사용'은 수업 자료로 복습하면 되고, **'수업에 없음'** 은 코드 주석과 이 표를 읽으며 따로 익힐 부분입니다. 새 코드에는 수업과 다른 부분을 주석에 `[수업에 없음]`으로 표시합니다.

**질문 4. 수업의 모델(DNN/CNN/RNN/Seq2Seq/Attention)을 프로젝트에서 어떻게 볼 수 있나** (ChatGPT 문서 2절을 정리)

**모델 구조 탐구 계획 (제안, 승인 후 진행)**

*미리 확인한 사실 (이 PC, `demucs` 4.1.0, `htdemucs`)* — **[확인: 실제로 불러서 센 값]**
- 출력 4개(drums·bass·other·vocals), 샘플링 44,100 Hz, 학습 구간 길이 `39/5`초(=7.8초), **파라미터 약 4,198만 개**
- **스펙트로그램 가지**(`encoder`·`decoder` 각 4층, `nfft=4096`, `hop=1024`, `cac=True`: 복소수를 실수 2채널로 쌓음)와 **파형 가지**(`tencoder`·`tdecoder` 각 4층)가 나란히 있고, 가운데에 **교차 변환기 `crosstransformer` 5층**이 두 가지를 연결
- `nn.MultiheadAttention` **10개**, `Conv1d` 80개, `Conv2d` 12개, **`nn.LSTM`은 0개**. 소스에는 이전 세대 Demucs의 `BLSTM` 클래스가 남아 있음(→ 수업 9강 RNN/LSTM과 "예전에는 LSTM, 지금은 Transformer"로 연결 가능, 세대별 설명은 [일반 지식])
- Whisper: `faster-whisper`는 **CTranslate2** 위에서 돌아서(PyTorch 모델이 아님) PyTorch의 forward hook으로 층을 들여다볼 수 없음 [확인: ctranslate2 4.8.4]. 단어별 시간은 `faster_whisper`의 `find_alignment`가 계산(함수 존재 [확인], 교차 어텐션과 DTW를 쓴다는 내부 설명은 [일반 지식])

*탐구 질문 3개 (프로젝트 증상과 연결)*
1. **Demucs는 어떻게 소리를 두 가지 표현(파형, 스펙트로그램)으로 동시에 보고, 어텐션으로 합치나?** — 모듈 트리 그림, 20초 클립의 층별 텐서 모양 기록(forward hook), 교차 변환기의 입력 시퀀스 길이, 어텐션 가중치 시각화(도전). 수업 연결: CNN(006), 인코더–디코더·U-Net 건너뛰기, Attention(011), Transformer(012), LSTM(009). **#35의 1~3번**(원곡·보컬·차이 스펙트로그램, 대역별 에너지 비율, 고정 필터 대조)이 "음역대가 달라서 분리된다"는 가설 검증이 됨.
2. **Whisper는 소리를 어떻게 글로 바꾸나?** — 입력 로그 멜(창 400·hop 160·Mel 80개 [확인]) 대 우리 그림(512·128·40 [확인])을 같은 클립으로 비교, 인코더–디코더 흐름도(자기회귀 디코딩, 교차 어텐션 [일반 지식]), 토큰 확률·`temperature`·`beam_size`. 수업 연결: 7강, 4강 Mel, 010·011·012.
3. **우리 앱에서 겪은 현상을 모델 구조로 설명할 수 있나?** — (a) 노래에서 VAD를 켜면 가사가 지워지고 `temperature=0.0`이면 반복 루프가 생기는 이유(자기회귀 디코딩과 온도 폴백), (b) 30초 창 때문에 언어 감지가 앞부분만 보는 점, (c) 단어 시간이 어긋나는 이유(어텐션 정렬은 추정), (d) 보컬이 깨끗하지 않은 구간(분리가 스펙트로그램 마스크처럼 근사하는 한계). 이것이 발표의 **"배운 점"** 이 됨.

| **LLM**                                          | **Large Language Model**(대규모 언어 모델). 글을 이해하고 만들어 내는 AI. 이 프로젝트에서는 **직접 쓴 연습 문장**의 뜻·연관 표현 설명에만 쓸 예정(L2)이고, 상업 노래 가사는 넣지 않습니다.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              | 계획서 L2(`explain.py`, 아직 없음), 검토 문서 10.4·13.1                                                                                                                                                                                                     |
| **API**                                          | **Application Programming Interface**. 프로그램이 다른 서비스의 기능을 부르는 창구. 이 프로젝트에서 API를 부르는 곳은 OpenAI TTS 하나이고, 부를 때마다 **과금**됩니다(그래서 캐시에 있으면 부르지 않음).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                | `tts.py`(`tts.calls`로 호출 횟수 기록), `.env`의 `OPENAI_API_KEY`                                                                                                                                                                                           |
| **CPU · GPU**                                    | **CPU = Central Processing Unit**(중앙 처리 장치, 일반 계산), **GPU = Graphics Processing Unit**(그래픽 처리 장치, 큰 모델 계산에 유리 **[일반 지식]**). 이 컴퓨터에는 GPU가 없어 모든 계산(Whisper, Demucs)을 CPU로 하고, 그래서 큰 모델과 분리가 느립니다.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            | `device="cpu"`, 검토 문서 15.2·15.4                                                                                                                                                                                                                         |
| **WAV · PCM**                                    | **WAV = Waveform Audio File Format**, 압축 없이 소리 숫자를 그대로 담는 파일 형식. **PCM = Pulse-Code Modulation**, 소리를 일정한 간격으로 재서 정수로 기록하는 방식이며 **PCM16**은 한 샘플을 16비트 정수로 기록한다는 뜻입니다. 이 프로젝트의 녹음은 스테레오 PCM16 wav입니다.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        | `recorder.save_wav`, `audio.py`(wav는 scipy, 그 밖의 형식은 `av`)                                                                                                                                                                                           |
| **스켈레톤 (skeleton)**                          | 계획서의 일부 기능을 앞당겨 **얇게 한 줄로 끝까지 관통**해 본 최소 동작 버전. 새 기능을 더하는 것이 아니라 "듣기 → 녹음 → 인식 → 채점 → 틀린 부분 표시"의 전체 흐름이 돌아가는지를 먼저 확인하는 것입니다. 발표 여부를 정하기 위해 11-01에 만들었고 지금의 `practice.ipynb`가 이어진 것입니다.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | `experiments/skeleton/주말_스켈레톤_시연_계획.md`, `experiments/skeleton/발표_대본_초안_스켈레톤.md`                                                                                                                                                        |
| **반복 루프 (repetition loop)**                  | 인식기가 **같은 단어나 구절을 끝없이 되풀이해 적는** 현상. Whisper는 방금 자기가 쓴 글을 보고 다음 단어를 고르는데(자기회귀 **[일반 지식]**), 어렵거나 무음·반주가 많은 소리에서 같은 구절이 계속 가장 그럴듯하게 뽑히면 끝까지 반복합니다. 정답에 없는 단어가 수십~수백 개 **삽입(I)** 으로 세어져 WER이 1을 훨씬 넘습니다. 이 프로젝트에서는 삽입 40개 이상인 7건이 모두 고유 단어 비율 0.01~0.04, 4단어 연속 반복 0.98~1.00이었습니다 **[확인: 지표]**. 폴백이 이것을 끊어 주는 역할을 한다고 알려져 있고 **[일반 지식]**, 그래서 폴백을 끈 `temperature=0.0`에서 더 잘 생기는지 확인 중입니다 **[미확인]**.                                                                                                                                                                                         | `clip_compare`의 반복 지표(분석용), 노트북 ⑥ 아래 칸, 검토 문서 13.5                                                                                                                                                                                        |
| **환각 (hallucination)**                         | 소리에 없는 말을 **만들어 적는 것**. 무음이나 음악만 있는 구간에서 Whisper가 말을 지어내는 경우가 알려져 있습니다 **[일반 지식]**. 반복 루프는 환각의 한 모양입니다. 강사님이 "모델이 무음까지 학습해서 문제가 될 수 있다"고 하신 것이 이것과 이어집니다. 그래서 무음을 거르는 VAD, 반주를 떼는 분리를 시험합니다.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      | 노트북 ⑥, 검토 문서 13.5, 15.2                                                                                                                                                                                                                              |
| **온도 폴백 (temperature fallback)**             | faster-whisper 기본 동작. 인식이 나쁘다고 판단하면(평균 로그확률이 낮거나 같은 말이 너무 반복되면) **온도(무작위성)를 0.0 → 0.2 → … → 1.0으로 올려 가며 무작위 샘플링으로 다시 인식**합니다. 반복을 끊는 데 도움이 되지만 같은 입력도 실행마다 결과가 달라질 수 있습니다. `temperature=0.0`을 주면 폴백이 꺼져 결과가 재현됩니다.                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | `stt.recognize(temperature=)`, 검토 문서 13.5                                                                                                                                                                                                               |
| **탐욕 디코딩 (greedy decoding)**                | Whisper는 글자(토큰)를 **하나씩** 이어 붙여 문장을 만드는데, 매 단계에서 **가장 확률이 높은 한 개만 고르는** 방식입니다. 앞날을 내다보지 않고 지금 가장 좋아 보이는 것을 고르므로 "탐욕"이라고 합니다. 우리 설정 `beam_size=1`이 이 방식이고(후보를 여러 개 들고 가는 **빔 탐색**을 쓰지 않음), `temperature=0.0`은 무작위 샘플링까지 끈 것이라 **같은 입력이면 항상 같은 문장**이 나옵니다(노래 14구간을 경로로 2회 인식해 모두 같았음 **[확인]**). 다만 앞 글자가 바뀌면 그 뒤가 모두 따라 바뀌므로 **입력 소리가 아주 조금만 달라도 반주가 섞인 노래에서는 문장이 크게 달라질 수 있습니다**(우리 16 kHz 변환 배열 대 경로 입력, 14구간 중 10구간 **[확인]**, 원인 **[추정]**). 기본 설정도 처음에는 같은 방식으로 시작하고 결과가 나쁠 때만 온도 폴백으로 넘어갑니다 **[일반 지식]**. 검토 문서 16.4 |
| **리샘플링 (resampling)**                        | 소리의 초당 표본 수(표본화 주파수)를 바꾸는 것. 44.1 kHz·48 kHz 녹음을 Whisper가 쓰는 16 kHz로 줄일 때 씁니다. 방법마다 결과 파형이 아주 조금 다릅니다(우리 `audio.py`의 `scipy.signal.resample_poly` 대 faster-whisper의 PyAV). 코드 설명은 `audio.py` 맨 위                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **`bytes`·`BytesIO`**                            | `bytes`는 파일 내용을 **메모리에 통째로 담은 값**. 웹 화면의 업로드·브라우저 녹음은 파일이 아니라 이 형태로 들어옵니다. `io.BytesIO`는 그 bytes를 **파일처럼 읽게 해 주는 표준 도구**라서 파일 경로를 받는 코드(scipy·PyAV·faster-whisper)에 그대로 넘길 수 있습니다(이슈 #37)                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| **F0 (기본 주파수, fundamental frequency)** | 목소리의 **음높이**. 성대가 1초에 떠는 횟수(Hz)이고, 억양·성조·노래의 음정을 이루는 재료입니다. 잡음이나 무성음 구간에서는 추정이 틀리기 쉽고(**옥타브 오류**: 실제의 2배나 절반으로 잡힘) 그래서 신뢰도를 같이 표시해야 합니다 [일반 지식]. | 아직 구현하지 않음. 억양 윤곽 비교 후보(`experiments/20261106 weekend ideas_claude code.md` 3절), Azure 운율은 영어만 제공 |
| **포먼트 (F1, F2)** | 입·혀 모양에 따라 스펙트럼에서 **에너지가 센 주파수 대역**. 낮은 쪽부터 F1, F2라고 부르고, **모음의 종류는 주로 F1·F2의 조합**으로 정해집니다. F0(성대의 떨림)와 다른 것으로, F0는 음높이, 포먼트는 입 모양이 만드는 울림입니다 [일반 지식]. | 아직 구현하지 않음. 모음 지도(F1–F2 평면) 아이디어 |
| **성조 (tone)** | **음높이의 변화 모양이 뜻을 바꾸는** 언어 특징. 중국어 4성+경성, 태국어 5성, 베트남어 6성(북부 기준) [일반 지식]. 베트남어는 성조 부호를 지우면 뜻이 달라지므로 악센트 기호를 없애지 않는 엄격 모드가 필요합니다(프랑스어 악센트 방침과 같은 이유). F0 윤곽으로 눈에 보이게 할 수 있습니다. | 아직 구현하지 않음. 지원 언어에는 중국어만 있음(`languages.py`) |
| **cent (센트)** | **음정 차이의 단위**. 반음 = 100 cent, 한 옥타브 = 1200 cent. 사람은 음높이를 Hz의 차이가 아니라 **비율**로 듣기 때문에 F0를 비교할 때 Hz 대신 씁니다 [일반 지식]. | 아직 구현하지 않음 (노래 음정 비교 후보) |
| **파열음 (plosive, stop)** | 입 안에서 공기 흐름을 **완전히 막았다가 터뜨려** 내는 자음. 영어 p·t·k·b·d·g, 한국어 ㅂ·ㅍ·ㅃ, ㄷ·ㅌ·ㄸ, ㄱ·ㅋ·ㄲ. 스펙트로그램에서는 **짧은 무음 뒤에 나오는 세로줄**(터지는 순간)로 보입니다. 영어는 유성·무성 2종, 한국어는 평음·격음·경음 3종으로 나뉘어서 한국어 화자에게 구분이 어려운 이유 중 하나로 설명됩니다 [일반 지식, 확인 필요]. 터진 뒤에 나오는 **숨**을 기식(aspiration)이라 합니다. | 아직 구현하지 않음. 아래 VOT와 같이 봄 |
| **VOT (Voice Onset Time)** | 파열음이 **터진 순간부터 성대가 떨리기 시작할 때까지의 시간**(ms). 영어 /p t k/는 기식이 있어 VOT가 길고, /b d g/는 짧아서 이 시간이 유성·무성을 가르는 단서가 됩니다 [일반 지식]. | 아직 구현하지 않음(고급 아이디어, 파열음 항목 참고) |
| **최소 대립쌍 (minimal pair)** | **소리 하나만 달라서 뜻이 달라지는 단어쌍**. 예: 영어 ship / sheep, light / right. 비슷한 소리를 **듣고 구별하는 훈련**에 씁니다. | 아직 구현하지 않음(TTS로 쌍을 만들어 퀴즈로 하는 아이디어) |
| **간격 반복 (SRS, Spaced Repetition System)** | **잊을 즈음에 복습**하도록 복습 간격을 점점 늘려 가는 학습 방법(예: 1일 → 3일 → 7일 뒤) [일반 지식]. | 아직 구현하지 않음. 기록 CSV가 재료이지만 문장 글을 저장하지 않는 원칙과 충돌해 설계가 필요 |
| **cloze (빈칸 채우기)** | 문장의 **일부를 가리고** 채우게 하는 연습. 받아쓰기에서 점수가 낮았던 단어 1~3개를 가리고 듣고 채우는 식으로 응용할 수 있습니다. | 아직 구현하지 않음 |
| **stem (스템)** | 음원 분리에서 **분리된 각각의 소리 트랙**. `htdemucs`는 drums·bass·other·vocals 4개의 stem을 냅니다. 원래는 음악 제작에서 악기군별로 묶어 내보내는 트랙을 부르는 말입니다 [일반 지식]. | `separate.py`는 vocals stem만 쓰고, `experiments/model anatomy/`의 노트북은 4개를 모두 봅니다 |
| **정답 stem (reference stem)** | 분리 성능을 재기 위한 **진짜 분리된 소리**(예: 스튜디오에서 보컬만 따로 녹음한 트랙). 모델이 낸 추정 stem을 이것과 비교해 SDR을 계산합니다. **상업곡에는 정답 stem이 없어서** SDR을 쓸 수 없고, 그래서 청취와 STT의 WER/CER로 대신 비교합니다. | 노트북에서는 **직접 만든 합성 믹스**(내 예문의 TTS 목소리 = 정답 stem + 합성 반주)로 해결 |
| **SDR (Signal-to-Distortion Ratio)** | 음원 분리 품질 지표(단위 dB). SDR = 10·log₁₀(Σ정답² ÷ Σ(정답−추정)²). **클수록 추정이 정답에 가깝습니다.** 정답 stem이 있어야만 계산할 수 있고, 크기 차이의 영향을 줄인 변형을 SI-SDR이라 합니다 [일반 지식]. | 노트북의 합성 입력에서 섞은 소리 −9.45 dB, 고정 대역통과 필터 2.98~4.38 dB, Demucs vocals 21.63 dB [확인: 11-06, 쉬운 입력이라 일반화 금지] |

### AI 세션의 검증은 "참고"입니다
AI 세션이 헤드리스로 돌린 결과는 **참고 baseline**입니다. 최종 확인은 VS Code에서 *File → Reload Notebook from Disk* 후 커널을 재시작하고 직접 실행해서 보는 것입니다.

## 6. 코드·수업 복습 계획 (제안)

강사님이 "AI가 써준 코드는 이해해야 한다"고 했고 코드는 매일 쌓이므로, 몰아서 하지 않고 **작게 나눠 꾸준히** 소화하는 것을 목표로 합니다. 정규 수업 시간표는 제가 몰라서, 정식 수업 시간은 **새 수업 내용을 놓치지 않는 것이 우선**이라고 보고 기본 계획에서는 뺐습니다. 수업이 복습·실습 위주인 날 프로젝트와 겹치는 주제(예: Whisper 수업 날 `stt.py`)가 나오면 그때 연결해서 보면 좋습니다.

| 시간                               | 길이              | 할 일                                                                                                                                      |
| ---------------------------------- | ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 출퇴근·쉬는 시간(모바일 GitHub 앱) | 5~10분            | **한 파일의 맨 위 docstring**(역할, 수업과의 관계)과 함수 이름만 읽기. 일지 2-1 읽는 순서 표, 5장 용어 표 읽기. 코드가 길면 읽지 말고 표만 |
