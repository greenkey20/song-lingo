## 2️⃣ ❓ 왜 만들었나

**화면**
- 노래로 외국어를 배울 때: 들리는 대로 따라 부르지만 **내가 맞게 말했는지, 어떻게 표기하는지, 무슨 뜻인지, 확인할 방법이 없다**
- 해결: 기준 음성과 내 소리를 **같은 음성 인식기**로 비교 + 받아쓰기 연습 + LLM이 해설해줌 
- 이 프로젝트의 또 다른 목적: **수업 내용을 실제 소리에 적용해 복습**

**대본**
> 노래로 외국어를 배우면 귀로 들은 대로 따라 하게 되는데, 제가 맞게 말하고 있는지, 어떻게 표기되는 문장인지, 무슨 뜻인지는 알기 어렵습니다. 그래서 기준 음성을 듣고, 제 소리를 음성 인식기에 넣어 정답과 비교해 봅니다. 또한 정답 음성을 듣고 받아쓰기를 하여 채점을 받거나, LLM의 해설을 볼 수 있도록 했습니다. 이 프로젝트는 부트캠프에서 배운 음성 처리와 API를 직접 써 보며 복습하는 목적도 있습니다.

## 3️⃣ 🔁 사용 흐름

**화면**
```
📝 노래 문장 선택 (또는 직접 입력)
   ↓
🔊 TTS 기준 음성 듣기
   ↓
 ┌───────────────┬──────────────────┐
 │ 🗣️ 따라읽기   │ ✍️ 받아쓰기        │
 │ 내 녹음 → 인식 │ 들은 대로 입력     │
 └───────┬───────┴─────────┬────────┘
         ↓                 ↓
   📊 오류율(WER·CER)과 틀린 부분 표시
```
- 따라읽기: 문장 표기와 뜻을 먼저 보여 줌
- 받아쓰기: 문장 표기는 **받아쓰기 답안 제출 뒤에** 공개

**대본**
> 사용 흐름은 이렇습니다. 노래 문장을 고르거나 직접 입력하면 먼저 기준 음성이 재생됩니다. 그 다음 두 가지 중 하나를 합니다. 따라읽은 녹음을 인식시키거나, 들은 소리를 받아 적습니다. 어느 쪽이든 결과는 오류율과 틀린 부분으로 나옵니다.

## 4️⃣ 🤖 핵심 모델 두 가지: 듣는 모델과 말하는 모델

**화면**

| | 👂 STT (소리 → 글자) | 🔊 TTS (글자 → 소리) |
| --- | --- | --- |
| 모델 | **Whisper** (OpenAI), 구현은 `faster-whisper` | **`gpt-4o-mini-tts`** (OpenAI API) |
| 이 프로젝트에서 하는 일 | 내 녹음을 글자로 바꿔 정답과 비교, 단어별 시간 제공 | 문장의 **기준 음성** 생성 |
| 어디서 도는가 | **내 컴퓨터(CPU)** → 녹음이 밖으로 나가지 않음 | **OpenAI 서버** → 문장 글자만 보냄, 호출당 과금 |
| 설정 | `tiny`(가장 작은 크기), int8, `beam_size=1`, 영어 지정 | 목소리 `alloy`, 결과는 wav, 캐시 |
| 입력 → 출력 | 소리(Log-Mel 그림 같은 표현) → 글자 | 글자 → 소리 파형 |

- Whisper 구조: **인코더**가 소리를 읽어 요약하고, **디코더**가 앞에서 낸 글자를 보며 다음 글자를 한 조각씩 예측 [일반 지식]
  - 수업의 6강에서 직접 만든 **작은 인코더–디코더(LSTM 기반)** 와 같은 큰 틀. Whisper 내부는 Transformer 계열이라 층의 종류는 다름 [일반 지식]
- 크기가 여러 가지(tiny~large) 중 **가장 작은 `tiny`**: 빠르지만 정확도는 낮을 수 있음 [일반 지식]
- 같은 STT로 **TTS 소리와 내 녹음을 모두** 인식시켜 비교 → 7장의 대조 실험

**대본**
> 이 프로그램의 핵심은 모델 두 개입니다. 듣는 쪽은 OpenAI가 공개한 Whisper로, 소리를 받아 글자로 바꿉니다. 수업에서 쓴 가장 작은 tiny 크기를 제 컴퓨터 CPU에서 돌려서 비용이 없고 녹음이 밖으로 나가지 않습니다. 말하는 쪽은 OpenAI의 TTS 모델로, 문장을 보내면 기준 음성을 받아 옵니다. 같은 인식기에 기준 음성과 제 녹음을 모두 넣어 비교하는 것이 이 프로그램의 기본 아이디어입니다.

## 5️⃣ 🧩 프로그램 구성과 수업 연결

**화면**

| 단계             | 기술                                                          | 수업과의 연결                |
| ---------------- | ------------------------------------------------------------- | ---------------------------- |
| 🔊 기준 음성      | OpenAI TTS (`gpt-4o-mini-tts`)                                | 013 OpenAI API               |
| 👂 인식           | `faster-whisper tiny` (CPU, int8)                             | 7강 Whisper                  |
| 📏 채점           | WER/CER, 편집 거리 역추적                                     | 보충 학습 + 단위 테스트      |
| 📈 소리 그림      | STFT, Log-Mel 스펙트로그램                                    | 03·lesson04                  |
| 🎯 틀린 구간 표시 | Whisper 단어별 시간 + 틀린 덩어리를 구간으로 변환(`align.py`) | 7강 Whisper 옵션 + 소리 그림 |

- 같은 문장은 TTS를 **캐시**(한 번 만든 음성 파일을 저장해 재사용)해 API 호출·비용을 아낌 [확인: 호출 횟수 `tts.calls`로 기록]

**대본**
> 프로그램 구성은 다섯 부분입니다. 기준 음성은 OpenAI TTS로 만들고, 사용자 음성 인식은 수업에서 쓴 faster-whisper tiny 모델을 CPU에서 돌립니다. 채점은 단어·글자 오류율 개념을 보충 학습하여 직접 구현했고 테스트도 붙였습니다. 그리고 수업에서 배운 STFT와 Log-Mel로 두 소리를 그림으로 비교하고, 틀린 구간이 그림의 어디인지 표시합니다. 기준 음성은 같은 문장이면 한 번만 만들어 파일로 저장해 두고 다시 쓰기 때문에, 반복 연습을 해도 API 호출과 비용이 늘지 않습니다.

## 7️⃣ 🔬 결과 살펴보기: 틀린 건 모델일까, 내 녹음일까

**화면**
- 3번 문장, **같은 Whisper tiny**에 두 가지 입력
  - 🤖 TTS 기준 음성 → `We'll sing together …` **WER 0.000** [확인]
  - 🎙️ 내 녹음 → `We are seeing together …` **WER 0.429** [확인]
- 모델이 이 문장을 못 알아듣는 것은 아님 → 원인은 **내 녹음 쪽**일 가능성 [추정]
- 🎨 소리 그림으로 비교 (파형, 스펙트로그램, Log-Mel)
  - 내 녹음: 앞 약 1.3초 무음, 저주파 잡음 띠, 단어 사이 빈틈이 적음 [확인, 그림]
- 🎯 **틀린 구간 표시** (`show_error_spans(3)`): 틀린 덩어리 `we'll sing`을 두 소리의 같은 번호 `[1]` 구간으로 나란히 표시 [확인]
  - TTS: 0.00~0.84초 / 내 녹음(`we are seeing`): 0.91~1.97초
  - 단어 시간은 Whisper의 **추정값**이라 대략의 구간이며, 원인을 알려 주지는 않음
- 💻 **수업에서 다루지 않은 부분의 코드** (`stt.py`, `align.py`, 노트북 `show_error_spans`)
  ```python
  _, words, _ = stt.recognize_words(path)               # Whisper: 단어마다 시작·끝 시간 (word_timestamps, VAD 사용)
  loc = align.locate_errors(정답, 내_단어, tts_단어)      # 틀린 연속 칸을 한 덩어리로 묶어 두 소리의 시간 구간으로 변환
  ax.axvspan(시작, 끝)                                   # 스펙트로그램 위에 같은 번호 [k]로 표시 (matplotlib)
  ```

**대본**
> 사용자 음성 인식에서 틀린 이유가 궁금해서 대조 실험을 했습니다. 같은 문장의 TTS 음성을 같은 모델에 넣으면 완벽하게 인식됩니다. 그러니 모델이 이 문장을 모르는 것은 아니고, 제 녹음 쪽에 이유가 있을 가능성이 큽니다. 수업에서 배운 스펙트로그램으로 두 소리를 비교하니 제 녹음은 앞에 긴 무음과 저주파 잡음이 있고, 단어 사이 빈틈이 적었습니다. 그리고 틀린 구간인 "we'll sing"이 두 소리에서 각각 어디인지 나란히 표시해 봤습니다. 이 부분은 수업에서 다루지 않아 직접 만들었습니다. 모델이 알려 주는 단어별 시작·끝 시간을 받아, 틀린 단어들을 시간 구간으로 바꾸고, 그림 위에 같은 번호로 칠하는 코드입니다. 기준 음성은 두 단어가 또렷하게 나뉘는데, 제 녹음은 이어진 하나의 소리로 보였습니다. 다만, 단어 시간은 모델이 추정한 값이라 대략의 위치이고, 이것이 인식 실패의 정확한 원인인지는 아직 확인하지 못했습니다.

> 현재 한계는 분명합니다. 지금은 영어 문장 세 개, 제 목소리 하나, 실험은 한 번이라 일반화할 수 없습니다. 또한, 사용자가 사용할 수 있는 화면은 노트북 파일이고, 웹페이지는 점검용만 있습니다. 브라우저에서 녹음해서 바로 인식하는 것은 Chrome과 Safari 모두 되는 것을 확인했지만, Safari는 앞부분이 끊기는 문제가 있습니다. 한편, 현재 따라읽기 채점 결과는 발음 점수가 아니라, 음성과 문장이 얼마나 일치하게 인식됐는지를 보는 값이라는 것입니다. 음성 인식기는 소리만 듣는 것이 아니라 앞뒤 단어의 흐름도 함께 보고 가장 그럴듯한 단어를 고르기 때문에, 발음이 조금 어긋나도 자연스러운 문장으로 적어 줄 수 있습니다. 그러면 발음이 부정확해도 일치로 채점될 수 있어서, 발음 점수라고 부르지 않습니다. 추가 개발 단계에는 제공 노래 연습 문장을 늘리고, 녹음 상태를 점검하는 기능을 추가하고자 합니다. 그리고 시간이 되면 LLM에 의한 뜻 설명, 음악·음성 분리 실험으로 넓혀 가겠습니다. 감사합니다.

## 9️⃣ 📚 용어 정리 (읽지 않고 화면으로만 보여 주는 장)

**화면**

| 용어                     | 한 줄 설명                                                                                                                                     | 예시                                                |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------- |
| 🎯 오류율 (WER / CER)     | 정답을 기준으로 틀린 비율 = (치환+삭제+삽입) ÷ 정답 길이. WER은 단어, CER은 글자 단위                                                          | 정답 `the cat sat`, 인식 `the cat sit` → 1÷3 = 0.33 |
| ✏️ 편집 거리              | 인식 결과를 정답으로 바꾸는 데 필요한 **최소 수정 횟수**(치환·삭제·삽입). 표를 채워 가며 구하고(동적 계획법), 되짚어 가면 어디를 고쳤는지 나옴 | `i love you` → `i you` : 삭제 1번                   |
| 🔁 치환 · 삭제 · 삽입     | 다른 단어로 바뀜 · 빠짐 · 없던 단어가 더해짐                                                                                                   | `[sat→sit]` `[-the-]` `[+are+]`                     |
| ⚠️ 오류율이 1을 넘는 경우 | 삽입이 많으면 가능. 그래서 "일치율"로 쓰지 않음                                                                                                | `hello` → `hello hello hello` : 2.0                 |
| 🧹 정규화                 | 비교 전에 대소문자·구두점·공백을 맞춤                                                                                                          | `Hello, World!` = `hello world`                     |
| 🧠 문맥 보정              | 인식기가 앞뒤 단어를 보고 그럴듯한 단어로 적는 성질. 그래서 점수는 **발음 점수가 아니라 인식 일치도**                                          | 흐린 소리도 문장에 맞는 단어로 적힐 수 있음         |
| 👂 STT / TTS              | 음성→글자 인식(Whisper) / 글자→음성 합성(OpenAI)                                                                                               |                                                     |
| 🌊 STFT · Log-Mel         | 소리를 짧은 구간마다 주파수별 세기로 나눈 그림 · 사람 귀에 맞춰 주파수를 40칸으로 묶고 로그(dB)로 본 그림                                      | 가로 시간, 세로 주파수, 색은 세기                   |
| 🔇 음성 구간 검출 (VAD)   | 말소리가 있는 구간만 골라내고 무음은 건너뜀                                                                                                    | 앞 1.3초 무음이 첫 단어에 섞이는 것을 줄임          |
| ⏱️ 단어별 시간            | Whisper가 단어마다 붙여 주는 시작·끝 시간. **추정값**이라 정확한 정렬은 아님                                                                   | `we'll` 0.00~0.40초 (예시 값)                       |
| 💾 캐시                   | 한 번 만든 결과를 저장해 두고 다시 사용                                                                                                        | 같은 문장의 TTS는 API를 다시 부르지 않음            |
| 🔢 int8                   | 모델 숫자를 8비트 정수로 줄여 CPU에서 빠르게 돌리는 설정                                                                                       | `compute_type="int8"`                               |

### ❓ 예상 질문과 준비한 답
| 질문                         | 답                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 발음을 평가하는 건가요?      | 아닙니다. Whisper 같은 인식기는 소리 한 조각만 보고 단어를 정하지 않고, **앞에 나온 단어들과 문장의 자연스러움**도 함께 보고 가장 그럴듯한 단어를 고릅니다 **[일반 지식]**. 그래서 소리가 조금 흐리거나 어긋나도 문맥에 맞는 단어로 **고쳐 적을 수 있고**, 그러면 발음이 불완전해도 정답과 일치해 오류율이 낮게 나옵니다. 예: `I want to explore the universe`를 `아이 원 투 익스플로어…`처럼 어색하게 말해도 인식기가 `explore`로 적어 주면 일치입니다(이 프로젝트에서 이런 경우를 실제로 확인한 것은 아니며 원리 설명입니다 **[미확인]**). 반대로 소리가 뚜렷하게 다르면 다른 단어로 적히기도 합니다(3번 문장의 `we'll sing`→`we are seeing`). 즉 이 값은 "내 소리가 인식기에 이 문장으로 들렸는가"이지 "원어민 발음에 얼마나 가까운가"가 아니라서, **문장 인식 일치도**로 정의했습니다. |
| 왜 tiny 모델인가요?          | GPU 없는 CPU 환경에서 수업 설정(tiny, int8)을 그대로 써서 속도와 재현성을 맞췄습니다. 더 큰 모델과의 비교는 **[미확인]**입니다.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| 3번 문장이 틀린 이유는?      | TTS는 맞게 인식되므로 모델 문제만은 아닌 것으로 보지만, 발음·속도·마이크·잡음 중 무엇인지는 **[미확인]**입니다(표본 1개).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| 오류율이 1을 넘을 수 있나요? | 네, 삽입이 많으면 가능합니다. 그래서 "일치율"로 바꾸지 않고 치환·삭제·삽입 개수를 함께 보여 줍니다.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| 틀린 부분 표시가 어색한데요? | 편집 거리가 같은 정렬이 여럿일 때 비슷한 단어끼리 짝짓도록 고쳤습니다(`we'll→we`, `+are`). 오류율은 그대로이고, 같은 거리의 다른 정렬이 선택되면 치환·삭제·삽입 개수가 달라질 수 있습니다.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| 틀린 구간 표시는 정확한가요? | Whisper가 추정한 단어 시간이라 대략의 구간입니다. 앞 무음이 첫 단어에 섞이는 것을 줄이려고 음성 구간 검출(VAD)을 켰지만 정확한 시작 시점은 **[미확인]**이고, 원인을 알려 주는 것이 아니라 같은 위치의 기준 소리를 나란히 보여 주는 용도입니다.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| 브라우저에서 녹음이 되나요?  | 점검용 화면에서 Chrome(webm/opus), Safari(mp4/aac) 모두 변환 없이 인식되고 서버 처리는 1~2초였습니다 **[확인]**. Safari는 앞부분이 끊겨 녹음되며 원인은 **[미확인]**입니다.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| wav로 녹음하나요?            | 브라우저 녹음은 wav가 아니지만 인식에는 문제가 없었습니다. 스펙트로그램을 그리려면 PCM으로 바꾸는 단계가 필요합니다(노트북의 `load_16k_mono`는 PCM16 wav만 읽습니다 **[확인]**). 인식 쪽은 `faster-whisper`가 내부에서 디코더 PyAV(`faster_whisper/audio.py`의 `decode_audio`, `av.open`)로 파일을 읽기 때문에 변환 없이 되었습니다 **[확인: 설치된 소스]**. **우리 저장소에는 이 변환·디코딩을 직접 확인하는 파일이 없고**, 점검 때 한 번 실행한 명령으로 두 형식의 코덱·길이를 읽어 본 것이 전부입니다(결과는 검토 문서 16.3 결과 발견 1). 인식 흐름은 `spike/server.py` → `stt.recognize`이고, PCM 변환 후 그림까지는 **[미확인]**입니다.                                                                                                                                               |
| 비용은?                      | 기준 음성은 한 번만 만들어 캐시하고, 인식은 로컬에서 하므로 반복 연습에 추가 호출이 없습니다.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
