# 개발환경·git 이슈 노트

이 프로젝트(song-lingo)에서 **개발환경(Python 환경, 노트북 커널, 마이크), git 작업 중 겪은 문제와 해결책**을 모아 두는 문서입니다. 새 문제가 생기면 "이슈 로그"에 번호를 이어 추가합니다. (학습 저장소의 `ict_innovation_sq_voice_ai/개발환경_이슈노트.md`와 같은 형식입니다.)

판단·옵션 비교는 `프로젝트_안내_및_주제_검토.md`, 하루 작업 기록은 `작업_일지.md`에 두고, 이 문서에는 **"이런 증상이 나오면 이렇게 한다"** 만 적습니다. 표시: [확인] 직접 실행해 확인, [추정] 동작으로 짐작, [일반 지식] 일반적으로 알려진 내용.

## 기본 환경 원칙

- **conda 환경 `voice-ai`(Python 3.11)만 사용합니다.** 경로는 `/opt/anaconda3/envs/voice-ai/bin/python`. `base` 등 다른 환경은 쓰지 않습니다.
- `numpy`는 **1.26.4 고정**입니다(TensorFlow 2.16이 `numpy<2`를 요구). 새 패키지는 설치 전에 `--dry-run`으로 numpy가 바뀌는지 봅니다.
- 노트북 커널이 `voice-ai`인지 확인: `import sys; print(sys.executable)` → `/opt/anaconda3/envs/voice-ai/bin/python`.
- 터미널 명령은 모두 **프로젝트 루트**에서 실행합니다(테스트가 루트의 모듈을 import함).

## 이슈 로그

### 환경·패키지

#### 1. 노트북에서 `.py`나 `.env`를 고쳤는데 반영이 안 됨 (예: `normalize() got an unexpected keyword argument 'unify'`)

- **증상**: 2026-11-03, `scoring.py`에 `unify` 인자를 추가한 뒤 노트북 셀에서 `TypeError: normalize() got an unexpected keyword argument 'unify'`. 이전에는 `.env`의 API 키를 바꿨는데도 같은 401 오류가 났음.
- **원인**: 노트북 커널은 **이미 import한 모듈과 `.env`를 다시 읽지 않습니다.** 메모리에 있는 옛 버전이 계속 쓰입니다 [확인: 재시작 뒤 해결].
- **해결**: 커널 재시작(Restart Kernel) 후 셀을 처음부터 다시 실행. `.py`·`.env`를 고쳤다면 항상 재시작합니다.
- **예방**: 오류 메시지가 "방금 고친 코드와 안 맞는" 내용이면 코드보다 먼저 커널 재시작을 의심합니다.

#### 2. 새 패키지를 깔다가 numpy가 올라갈 위험

- **배경**: 학습 저장소 이슈 노트 #9에서 `ultralytics` 설치가 `numpy`를 2.x로 올려 TensorFlow import가 깨진 적이 있습니다.
- **이 프로젝트의 방식**: 설치 전 `$PY -m pip install <패키지> --dry-run`으로 바뀌는 목록을 보고, numpy가 포함되면 설치하지 않습니다. 2026-11-03 `sounddevice==0.5.6`도 dry-run으로 numpy 불변을 확인한 뒤 설치했습니다 [확인].
- **설치 후 점검**: `$PY -m pip list | grep -i -E "numpy|tensorflow"`, `$PY -m pip check`.

#### 3. `pytest`가 없음

- 이 환경에는 `pytest`가 없습니다. 테스트는 표준 라이브러리 `unittest`로 합니다: `$PY -m unittest discover -s tests -v`.

#### 4. 마이크 녹음(`sounddevice`)이 안 됨 / 권한

- **준비**: `sounddevice==0.5.6` 설치됨(`requirements.txt`). 녹음은 터미널의 `scripts/record_takes.py`로 하고, **Claude는 마이크 권한이 없어 실행하지 않습니다.** 사용자가 직접 실행합니다.
- **macOS 마이크 권한**: 터미널(또는 VS Code)에 마이크 권한이 없으면 소리가 안 들어오거나 오류가 납니다. 시스템 설정 → 개인정보 보호 및 보안 → 마이크에서 사용 중인 앱을 허용합니다 [일반 지식].
- **장치 확인**: `$PY scripts/record_takes.py --devices`. 내장 마이크는 보통 44.1 kHz, 2채널로 잡힙니다 [확인: 2026-11-03 녹음 27건]. 입력 채널이 1개뿐인 장치는 같은 소리를 양쪽에 복사해 스테레오로 저장합니다.
- 사용법 전체는 `연습_문장_데이터_설명.md` 5.1.

#### 5. OpenAI API 키가 적용되지 않거나 과금이 걱정될 때

- 어떤 키가 쓰이는지는 `$PY scripts/check_api_key.py`(값은 가려서 보여 줌). `.env`를 읽으므로 **Claude는 실행하지 않고** 사용자가 `! $PY scripts/check_api_key.py`로 실행합니다.
- 키를 바꾼 뒤에는 커널 재시작(#1).
- 과금이 나는 곳은 TTS 한 곳이고, 캐시(`data/tts_cache/`)에 없는 문장일 때만 호출됩니다. 노트북의 `GENERATE_MISSING_TTS`가 `True`이면 없는 문장을 새로 만들어 과금될 수 있습니다.

#### 14. `pip install demucs`가 `sphn` 빌드 실패로 중단됨 (2026-11-03)

- **증상**: `$PY -m pip install demucs` 끝에 `Failed to build installable wheels for some pyproject.toml based projects` / `sphn`. `--dry-run`에서는 `demucs-4.1.0 einops julius lameenc safetensors sphn`이 설치될 것으로 보였음.
- **원인**: 의존 패키지 `sphn`의 휠을 이 환경(Python 3.11, macOS 13 Intel)에서 받지 못해 소스 빌드로 넘어갔고 실패함 [추정: 휠이 없어서; 빌드 로그 원인은 확인하지 않음]. 설치가 중단되어 환경은 변하지 않았음(numpy 1.26.4, torch 2.2.2 [확인]).
- **해결**: `sphn` 없이 `$PY -m pip install --no-deps demucs`, 이어서 `$PY -m pip install --no-deps einops julius lameenc safetensors`. `demucs.pretrained`·`demucs.apply`·`demucs.audio` import와 `htdemucs` 분리 실행이 됨 [확인]. `sphn`이 필요한 기능이 있는지는 [미확인].
- **알아둘 점**: `--dry-run`이 통과해도 소스 빌드 단계의 실패는 예측하지 못함. `--no-deps`로 깔면 빠진 의존 패키지가 import 때 드러나므로 설치 직후 `import`와 짧은 실행으로 확인한다.

### 노트북

#### 6. Read 도구로 `practice.ipynb`를 열면 너무 큼

- **증상**: 출력(base64 오디오, 그림)까지 통째로 나와 토큰 한도를 넘습니다.
- **해결**: 셀 구조는 `json`으로 읽습니다. 수정은 NotebookEdit을 쓰되, 그것이 막히면 JSON을 직접 고치고 **바이트 왕복 동일·코드 AST 동일**을 확인합니다(2026-11-03 주석 추가 때 이렇게 함 [확인]).

#### 7. 노트북 출력에 개인정보·경로·오디오가 박힘 → 커밋은 "출력 지운 정리본"으로

- **위험**: 출력에 `<audio>` base64(내 목소리), `/Users/…` 경로, key가 들어갈 수 있고 저장소는 공개입니다.
- **절차**: ① 출력을 지운 정리본을 임시 파일에 만든다(스크래치패드) ② `$PY scripts/scan_outputs.py <정리본>`이 "깨끗합니다"인지 확인 ③ `git hash-object -w <정리본>` ④ `git update-index --cacheinfo 100644,<해시>,practice.ipynb`로 인덱스에만 넣는다 ⑤ 커밋.
- **결과**: 로컬 원본(출력 있음)은 그대로 두고 커밋에는 정리본이 들어갑니다. 그래서 **`git status`에 `M practice.ipynb`가 계속 남는 것은 정상**입니다.

#### 15. 노트북에서 분리(③b) 뒤 비교(⑥)를 실행하면 커널이 죽음 — `OMP: Error #15` (2026-11-03)

- **증상**: `experiments/song_vocal_separation.ipynb`에서 ③b(Demucs 분리)를 실행한 같은 커널에서 ⑥(Whisper 인식 비교)을 실행하면 `The Kernel crashed while executing code in the current cell or a previous cell.` 새 터미널 프로세스에서 같은 비교(`scripts/compare_clips.py`)는 오류 없이 끝까지 돌았음(8구간 × 2 = 16번 인식 2분 51초) [확인].
- **원인**: 한 프로세스에서 `torch`(Demucs)와 `CTranslate2`(faster-whisper)를 함께 불러오면 **OpenMP 런타임(`libiomp5.dylib`)이 두 번 초기화**되어 프로세스가 중단됨. 재현 [확인]: `torch` + `get_model("htdemucs")` 다음 `stt.recognize`를 같은 프로세스에서 실행하면 `OMP: Error #15: Initializing libiomp5.dylib, but found libiomp5.dylib already initialized.`와 함께 종료 코드 134. 노트북에서는 이 오류 메시지가 보이지 않고 "커널이 죽었다"로만 나옴.
- **해결(택 1)**:
  1. **커널 재시작 후 ⑥만 실행**: ①(설정) → ②(CLIPS) → ⑤(정답 상태) → ⑥ 순서로 실행하고 ③b는 실행하지 않는다. 분리는 이미 끝나 파일에 있으므로 다시 할 필요가 없다. (분리를 더 하려면 다시 재시작: 같은 커널에서 두 가지를 쓰지 않는다.)
  2. **분리를 별도 프로세스로 실행**(근본 해결, 적용함): 노트북 ③b가 `scripts/separate_clip.py --separate-only`를 `subprocess`로 부르게 바꿨다. 6초 임시 구간으로 확인했고 [확인] 실행 뒤 커널의 `sys.modules`에 `torch`·`demucs`가 없었다. 대신 구간마다 새 프로세스라 torch 불러오기와 모델 읽기(수 초)가 매번 든다. 이 방법을 적용한 노트북에서는 1번(재시작)이 필요 없다.
  3. **쓰지 말 것**: 환경 변수 `KMP_DUPLICATE_LIB_OK=TRUE`로 오류를 끄는 방법. 오류 메시지 자체가 "충돌하거나 **조용히 틀린 결과**를 낼 수 있다"고 경고하며, 이 프로젝트는 측정값을 비교하는 실험이라 조용한 오류가 가장 위험하다.
- **알아둘 점**: 순서가 반대(Whisper → 분리)여도 같은 충돌이 날 것으로 보임 [추정]. 터미널 스크립트는 프로세스가 따로라 문제없음.

### git

#### 8. `git checkout main`이 "Your local changes to the following files would be overwritten" 로 막힘

- **증상**: 2026-11-03, 브랜치를 머지한 뒤 `main`으로 전환하려는데 `practice.ipynb`가 덮어쓰일 수 있다며 중단.
- **원인**: 로컬 `practice.ipynb`는 출력이 있는 원본이고 커밋된 것은 정리본이라, 항상 "수정됨"으로 보입니다(#7). 브랜치를 바꾸면 git이 이 파일을 다른 내용으로 바꿔야 해서 막습니다.
- **해결** [확인]:
  ```bash
  cp practice.ipynb <스크래치패드>/practice_local_with_outputs.ipynb   # 1) 원본 백업
  shasum practice.ipynb <백업 파일>                                    #    해시가 같은지 확인
  git restore practice.ipynb                                           # 2) 작업 사본을 커밋 상태로
  git checkout main && git pull                                        # 3) 전환·갱신
  cp <백업 파일> practice.ipynb                                        # 4) 원본 복원 → 다시 M 상태(정상)
  ```
- **주의**: `git restore`는 로컬 변경을 버리므로 **반드시 1)의 백업과 해시 확인 뒤에** 합니다. `git stash`도 가능하지만 노트북 JSON이 커서 백업 파일 방식이 더 눈에 보입니다 [추정].
- 노트북을 VS Code에서 열어 두었다면 *File → Reload Notebook from Disk*.

#### 9. 머지 후 `git pull`이 "Your configuration specifies to merge with the ref 'refs/heads/feat/...' ... no such ref was fetched"

- **증상**: `main` 전환이 막힌 상태(#8)에서 `git pull`을 하면 `feat/…` 브랜치의 업스트림을 찾지 못한다는 메시지. 동시에 `origin/main`은 정상으로 가져옴(`85f5038..cc23a35`).
- **원인**: 머지된 뒤 **원격의 작업 브랜치가 지워졌습니다**(`git ls-remote --heads origin`에 `main`만 있음 [확인]). 지워진 이유(저장소의 "머지 후 브랜치 자동 삭제" 설정인지)는 확인하지 않았습니다 [미확인]. 로컬 브랜치의 업스트림 설정만 남아 있어 나온 메시지입니다.
- **해결**: 오류가 아니라 안내입니다. `main`으로 전환해서 pull하면 됩니다(#8). 로컬 브랜치는 필요 없으면 `git branch -d feat/recorder-normalization`, 남아 있는 원격 추적 참조는 `git fetch --prune`으로 정리합니다.

#### 10. `git add -A` / `git add .` 금지 — 파일을 하나씩 추가

- **이유**: 이 저장소는 공개이고, 작업 폴더에는 내 녹음(`data/`), 결과(`results/`), 모델(`models/`), `.env`처럼 올리면 안 되는 것이 있습니다(대부분 `.gitignore`로 막혀 있지만, 새 파일 이름이 우회될 수 있음).
- **방법**: `git add <파일>`을 하나씩, 매번 `git status`로 확인. 커밋 전 `git ls-files data results models .env`가 비어 있는지 봅니다(2026-11-03 [확인]).

#### 11. 문서에 내 컴퓨터의 절대 경로가 들어감

- **증상**: 설명 문서에 `cd /Users/<계정>/…`처럼 홈 폴더 경로가 적힘 → 공개 저장소에 계정명이 노출.
- **해결**: `cd <song-lingo 프로젝트 폴더>`처럼 자리표시자로 씁니다. 커밋 전 `git diff --cached | grep -n "/Users/"`로 확인합니다.

#### 12. 커밋·이슈 연결 규칙 (헷갈릴 때)

- 메시지에 **`Refs #N`** 만 씁니다. `Closes #N`을 쓰면 머지 때 이슈가 자동으로 닫히는데, **이슈를 닫는 것은 사용자의 판단**입니다(2026-11-03 PR #30에서 Refs만 써서 이슈 #3·#10·#25·#29가 열려 있는 상태로 머지됨 [확인]).
- 보드(GitHub Projects)는 `gh project`가 없어 `gh api graphql`로 바꿉니다(ID는 `CLAUDE.md`).

## 자주 쓰는 진단 커맨드 모음

```bash
PY=/opt/anaconda3/envs/voice-ai/bin/python

# 1. 환경과 핵심 버전
$PY -c "import sys, numpy; print(sys.executable, numpy.__version__)"     # numpy 1.26.4
$PY -m pip list | grep -i -E "numpy|tensorflow|faster-whisper|sounddevice"
$PY -m pip check

# 2. 새 패키지 설치 전 (numpy가 바뀌면 설치하지 않는다)
$PY -m pip install <패키지> --dry-run

# 3. 전체 테스트
$PY -m unittest discover -s tests

# 4. 커밋 전: 올라가면 안 되는 것이 추적 중인지, 노트북 출력, 절대 경로
git ls-files data results models .env       # 아무것도 안 나와야 함
$PY scripts/scan_outputs.py <정리본.ipynb>   # "깨끗합니다"
git diff --cached | grep -n "/Users/"        # 아무것도 안 나와야 함

# 5. 브랜치 상태
git ls-remote --heads origin                 # 원격에 있는 브랜치
git fetch --prune && git branch -vv          # 사라진 원격 브랜치 정리·확인

# 6. 마이크 장치 목록 (사용자가 직접)
$PY scripts/record_takes.py --devices
```
